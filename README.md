# LINKSHOT · 링크샷

**6개 전장 · 20종 무기 · 무기 색상 6종 · 남녀 캐릭터 2종 · 캐릭터 외형 5종**을 제공하는 브라우저 3D FPS 프로토타입입니다. 기기별 누적 전적·무기 숙련도와 포인트, 영구 무기 해금·외형 상점이 포함되어 있으며 두 실행 방식을 지원합니다.

- **1인 플레이 / Vercel / Windows 패키지:** 봇과 전투 판정이 브라우저의 Web Worker에서 실행됩니다. 게임 서버나 Node.js 설치 없이 플레이합니다.
- **LAN 멀티플레이:** `npm start`로 Node.js 서버를 열고 같은 네트워크에서 최대 8명이 플레이합니다. 서버에서 이동·충돌·사격·피격·점수를 판정합니다.

계정, 유료 API, 외부 게임 서버가 필요하지 않습니다. `~/engine`은 개발 시 이미지 제작에만 사용하며 플레이할 때는 필요하지 않습니다.

## 비개발자 친구에게 전달하기 (Windows 1인 플레이)

### 가장 간단한 방법: Vercel 링크

Vercel에 배포한 주소를 보내면 친구는 최신 **Edge 또는 Chrome**에서 주소를 열기만 하면 됩니다. Node.js/npm/Python을 설치할 필요가 없습니다. Vercel 배포 절차는 아래를 참고하세요.

### 파일로 보내기: Windows 포터블 ZIP

제작하는 컴퓨터에서 한 번 실행합니다.

```sh
npm install
npm run setup:packaging   # 최초 1회. 프로젝트 전용 Go 컴파일러 다운로드 + SHA-256 검증
npm run package:windows   # 1인 플레이 빌드 → Windows x64 EXE → ZIP
```

친구에게 **`release/LINKSHOT-Windows-x64.zip`만 전달**하면 됩니다.

1. ZIP을 **압축 해제**합니다.
2. 안에 있는 **`LINKSHOT.exe`를 더블클릭**합니다.
3. 기본 브라우저가 열리면 전장·무기·스킨을 고르고 **연습전 시작 → 교전 시작**을 누릅니다.
4. 게임 중에는 작은 실행 창을 열어 두고, 끝나면 그 창을 닫습니다.

실행 파일 안에 게임과 정적 웹서버가 포함되어 있습니다. **설치, 관리자 권한, 인터넷, Node.js, Python, Go가 친구 컴퓨터에 필요하지 않습니다.** 브라우저 및 WebGL 지원은 필요합니다. 서버는 `127.0.0.1`에만 열리며 LAN/인터넷으로 게임을 공개하지 않습니다. 기본 포트 `27007`이 사용 중이면 빈 포트를 자동 선택합니다. 브라우저가 자동으로 열리지 않으면 실행 창에 나온 URL을 직접 여세요.

전적/포인트/구매 외형은 **현재 Windows 사용자의 설정 폴더에 있는 `LINKSHOT/profile.json`**에 저장됩니다. 일반적인 Windows 환경에서는 `%APPDATA%\LINKSHOT\profile.json`입니다. 새 ZIP으로 교체하거나 브라우저 저장소를 지워도 이 파일은 유지됩니다. 실행 파일이 이미 켜져 있으면 가능한 경우 기존 로컬 실행 창을 재사용합니다. 저장 API는 로컬·동일 출처 요청만 허용하고, 파일은 임시 저장 후 교체합니다.

> Windows 10/11 x64 대상입니다. ARM64 패키지가 필요하면 `npm run package:windows -- --arm64`를 사용하세요. 빌드 컴퓨터에는 Go가 필요하며, 위 자동 설치는 macOS/Linux에서 시스템을 변경하지 않고 `.toolchain/`에만 설치합니다. Windows에서 빌드할 때는 [Go](https://go.dev/dl/)를 설치하세요. 실행 파일은 서명되지 않은 개인 테스트용이므로 SmartScreen/보안 소프트웨어의 확인 또는 차단이 있을 수 있습니다. 출처 및 `release/*.sha256`을 확인하고 보안 정책을 따르세요. 폭넓게 배포할 때는 코드 서명을 고려하거나 Vercel 링크를 사용하세요. Mac에서 교차 빌드한 파일의 실제 Windows 실행은 별도 확인이 필요합니다.

## 1인 플레이 빌드와 Vercel 배포

빌드하는 컴퓨터에만 Node.js 22 이상이 필요합니다.

```sh
npm install
npm run build        # 정적 1인 플레이 사이트 → dist/
npm run preview      # http://localhost:4173
```

`dist/`는 정적 웹사이트입니다. 플레이 중 Node.js를 실행할 필요가 없으며, Vercel/Nginx/Apache 등 정적 호스팅에서 실행합니다. Node 없이 로컬 확인을 하려면 Python이 있는 컴퓨터에서 `python3 -m http.server 8000 --directory dist`도 가능합니다. ES 모듈과 Web Worker 때문에 `dist/index.html` 더블클릭(`file://`)은 지원하지 않습니다. Windows 친구에게는 위 EXE 또는 Vercel 주소를 사용하세요.

**GitHub Actions는 Vercel 배포에 필요하지 않습니다.**

1. 이 프로젝트를 GitHub 저장소에 올립니다. `public/assets/`의 생성 이미지도 포함하고, `node_modules/`, `.toolchain/`, `artifacts/`, `release/`, `dist/`는 올리지 않습니다.
2. Vercel에서 **Add New → Project → 해당 GitHub 저장소 Import**를 선택합니다.
3. Framework는 **Other**, Build Command는 **`npm run build`**, Output Directory는 **`dist`**입니다. 포함된 `vercel.json`이 이 값을 설정합니다.
4. **Deploy**를 누르고 생성된 HTTPS 주소를 공유합니다. 이후 연결한 브랜치에 push하면 자동 배포됩니다.

이 배포에는 `/api`나 WebSocket 서버가 필요하지 않습니다. 1인 플레이는 `shared/simulation.js`를 브라우저 워커에서 실행합니다. LAN 버전의 메모리 기반 방 서버를 Vercel Functions에 그대로 올리는 구성이 아닙니다. Actions는 선택적으로 테스트 CI에만 사용할 수 있습니다. GitHub 업로드와 Vercel 배포는 별개이며, 사이트 공개는 Vercel에서 이 저장소를 Import한 뒤 진행합니다.

## LAN 멀티플레이 실행

Node.js 22 이상이 필요합니다.

```sh
npm install
npm start
```

- 이 컴퓨터: **http://localhost:3000**
- 친구: 터미널 또는 로비에 표시되는 **http://192.168.x.x:3000** 같은 LAN 주소
- 서버는 기본적으로 `0.0.0.0:3000`에서 수신합니다. 포트 변경: `PORT=8080 npm start`
- 개발 중 자동 재시작: `npm run dev` (재시작하면 진행 중인 방은 초기화됩니다.)

### 친구와 플레이

1. 서버 컴퓨터와 같은 Wi-Fi/유선 LAN에 접속합니다.
2. 한 명이 **LAN 대전 → 방 만들고 출격**을 누릅니다.
3. 게임 메뉴에서 **친구 초대 링크 복사**를 누르고 친구에게 전달합니다. 친구가 링크를 열면 같은 방으로 바로 참가합니다.
4. 또는 같은 LAN 주소로 접속한 뒤 **5자리 방 코드**를 입력하거나 **열린 방 보기**에서 참가합니다.
5. 각자 **교전 시작**을 클릭하면 마우스가 잠기고 조작을 시작합니다. `Esc`로 커서를 해제합니다.

> 접속되지 않으면 macOS의 로컬 네트워크 권한 및 방화벽에서 Node.js를 허용하세요. 게스트 Wi-Fi의 AP/client isolation은 기기 간 접속을 차단할 수 있습니다. 친구에게 `localhost`를 공유하면 안 됩니다. 인터넷 공개 서버를 전제로 만든 보안/인증 시스템은 없으므로 공유기 포트포워딩 없이 신뢰할 수 있는 LAN에서 사용하세요.

## 플레이 모드와 튜토리얼

로비에 **튜토리얼 / 혼자 연습 / LAN 대전 / 일반 / 랭크** 다섯 진입 경로를 표시합니다.

- **튜토리얼·혼자 연습:** 정적 배포와 LAN 에디션 모두 브라우저 Web Worker로 실행합니다. LAN WebSocket이 끊겨도 이용할 수 있습니다.
- **LAN 대전:** 기존 로컬 Node.js 서버의 방 생성/참가·초대를 유지합니다. 정적 HTTPS 사이트에서는 사설망 서버를 자동 탐색하거나 직접 WebSocket 연결하지 않고, 사용자가 입력한 로컬 서버 페이지를 여는 방법을 안내합니다.
- **일반·랭크:** 중앙 온라인 서버가 아직 구성되지 않아 **이용 불가 사유를 표시**합니다. 대기열/레이팅/랭크가 구현되거나 연결된 것처럼 동작하지 않습니다. 이후 계정·인증·매칭·전적·점수 서버는 **Java/Spring Boot** 기준으로 구성하며, 실시간 전투 판정의 배치 방식과 인증·DB·운영 정책은 후속 단계에서 확정합니다. 기존 LAN 서버를 그대로 인터넷에 공개하는 기능은 아닙니다.

튜토리얼은 멀티플레이 맵 풀과 분리된 작은 훈련장에서 **실제 입력·충돌·사격·장비·리스폰 규칙**으로 진행합니다. 시점/WASD/달리기 → 점프/앉기/계단 → 표적/정조준/재장전 → G/나이프/줍기 → 초급 AI 교전 → 3초 리스폰 시범의 여섯 단계입니다. HUD에 목표와 이동 위치를 표시하고 달성하면 자동으로 넘어갑니다. 사망해도 현재 학습 단계는 유지하며 Esc 메뉴에서 다시 시작하거나 혼자 연습으로 건너뛸 수 있습니다. 첫 실행 추천은 닫을 수 있고 언제든 재실행할 수 있습니다.

튜토리얼은 **킬/데스·무기 숙련도·LP·라운드 보상과 경쟁 점수에 반영하지 않습니다.** 완료 여부만 브라우저에 표시용으로 저장합니다. 온라인 모드의 기록도 기존 로컬 장부와 명시적으로 분리합니다.

## 구현된 내용

- 8개 독립 레이아웃, 충돌·점프·엄폐물·그림자, 맵별 봇 경로 탐색과 미니맵
- 전장마다 실제로 올라설 수 있는 **계단식 발판 3–4개와 추가 엄폐물 12개**를 배치했습니다. 야시장은 좁은 비대칭 동선에 맞춰 발판 3개, 나머지 전장은 4개입니다. 낮은 계단은 걸어서 오르내리고, 1.8m 발판은 계단이 없는 면에서도 점프로 올라갈 수 있습니다. 가장자리 지지/착지는 측면 충돌과 같은 범위를 사용하며, 발판 밖으로 벗어나면 중력이 적용됩니다. 높은 위치는 실제 사격 시야에도 반영됩니다.
- `C` 또는 `Ctrl`을 누르는 동안 앉기: 낮아지는 시점·머리/몸통 피격 범위, 느린 이동과 조용한 발소리, 낮은 엄폐 뒤 숨기. 머리 위 공간이 부족하면 자동으로 앉은 자세를 유지합니다.
- 최대 8명 개인전, 5자리 방 코드, 여러 방, 초대 링크, 방장 자동 위임
- 최대 8명 LAN 대전, 0–7개 연습 봇(사람이 참가하면 봇이 비워짐), 초급/중급/고급 선택. 정적 배포는 1인+최대 7봇입니다.
- 봇끼리도 싸우는 개인전 AI: 인간 우선 타기팅 없음, 0.6–1.0초 반응 지연, 약 63°/초의 느린 몸 회전, 지연된 위치 추적과 조준 오차
- 초급 봇의 기본 자동소총 사격은 명중률이 낮은 짧은 2–3발 연사를 사용하며, 탄 사이 최소 0.45초와 연사 후 0.65–1.0초 휴식이 있습니다. 고유 3점사 무기의 점사 내부 주기는 무기 설정을 따릅니다. 봇 난이도가 플레이어의 무기 피해량이나 마우스 감도를 바꾸지는 않습니다.
- 위 봇 설정은 **초급(기존 반응/조준 설정)**입니다. 중급은 반응 350–550ms·최소 탄 간격 300ms, 고급은 반응 180–300ms·최소 탄 간격 180ms이며 무기 자체의 발사 주기보다 빨라지지 않습니다. 봇은 소총·SMG·산탄총·저격총·권총·LMG·DMR을 나눠 들고 플레이어와 동일한 무기별 피해/거리 감소/헤드샷을 적용합니다. 기존 15 고정 피해 보정은 제거했습니다. 체력은 모두 100입니다.
- 8개 전장에 **6–9m 높이의 진입 가능한 건물 34개와 추가 엄폐벽 64개**가 있습니다. 실제 실내 계단·중간층·옥상·출입문을 사용하며, 창이 없는 막힌 패널/계단실과 열린 사격창을 섞었습니다. 창과 문은 보이는 대로 이동/사격 판정에도 반영됩니다.
- 돌격소총·기관단총·산탄총·저격소총·권총·경기관총·지정사수소총, 무기별 탄창/연사/재장전/반동/효과음, 헤드샷과 거리별 피해량
- 무기별 걷기/달리기 속도와 정조준 이동 페널티: 권총/기관단총은 가볍고 경기관총/저격총은 무겁습니다. 라이플 정조준은 실제 사격과 같은 시점/각도를 사용하며, 화면 반동 때문에 조준점과 탄착점이 어긋나지 않습니다.
- 산탄총 8개 산탄의 개별 피격 판정, 저격 스코프, 무기별 독립 탄창, 재장전 취소 및 교체 지연
- 무기와 캐릭터 공통 스킨 6종, 실제 3D 장비 미리보기, 시작 장비/전장/스킨 브라우저 저장
- 서버 권위 이동 및 피격 판정, 사격 속도 제한, 오래된 입력 자동 해제
- 3초 리스폰, 1.5초 스폰 보호 (사격하면 해제)
- 맵당 34–66개 스폰: 지상 24곳과 2·3층·옥상. 스폰 전용 ㄷ자 벽 대신 건물·화물·설비로 시야를 가리고 적에게 보이지 않는 지점을 우선 선택합니다.
- 사망 후 입력·총성·섬광·예측 점사를 클라이언트와 서버에서 차단합니다. 3초 대기에 처치한 상대·무기·해당 무기의 숙련도 레벨을 표시합니다.
- 타이머 아래 킬·더블킬·트리플킬 등 연속 처치 효과와 무기 레벨·진행 게이지. 연속 처치는 5초 이내 다음 킬로 이어지며 사망하면 초기화됩니다.
- 5분 또는 20킬 라운드, 점수판, 킬 피드, 방장 재경기
- 미니맵 (시야 내 상대만 표시), 실제 녹음 총성과 로컬 효과음, 감도·FOV·음량·그래픽 설정
- 내 발소리와 주변 플레이어/봇의 공간 발소리: 실제 지상 이동 거리로 보폭을 계산하며 달리기는 빠르고 크고, 앉기는 작고 조용합니다. 정지·사망·공중·리스폰/순간이동에는 잘못된 발소리를 내지 않습니다.

산탄총/저격총/반자동 권총/지정사수소총은 클릭할 때마다 한 발씩 발사하며 Glock 18C는 자동권총입니다. **생존 중 숫자키·휠·임의 네트워크 입력으로 무기를 바꿀 수 없습니다.** 사망 후 E로 보유 무기를 선택하면 다음 부활부터 적용하고, 선택 대기는 사망 후 최대 15초입니다. 선택 후 마우스 잠금을 복원하며 브라우저가 거절하면 재개 버튼을 표시합니다. 앉기·일어서기는 약 100ms 동안 눈높이·피격 범위·이동속도와 몸체 모션이 함께 전환됩니다. 달리기·공중에서는 새로 앉을 수 없고, 낮은 천장 아래의 강제 앉기는 안전하게 유지합니다.

G는 바닥 장비와의 명시적인 상호작용만 허용합니다. 1.8m 이내·높이 차 1.25m 이내의 총 중 벽/바닥을 뚫지 않고 닿는 가장 가까운 총을 서버가 고릅니다. 총을 들고 주우면 이전 총을 떨어뜨리며 **남은 탄약과 총기 색상을 그대로 교환**합니다. 재장전/점사/누르던 방아쇠는 취소하고 350ms 준비 시간을 적용합니다. 총이 없으면 나이프를 들고, 나이프는 버릴 수 없습니다. 기본 나이프는 사거리 1.85m·45 고정 피해·공격 간격 550ms로 벽/스폰 보호를 존중하며 헤드샷 배율이 없습니다. 드롭은 중력으로 해당 층 바닥에 내려앉고 60초 뒤 사라지며 방당 최대 32개, 재경기에는 모두 정리합니다.

주운 미해금 총도 해당 생명 동안 사용할 수 있지만 **영구 소유권·상점 포인트·저장된 다음 부활 장비는 바뀌지 않습니다.** 나이프 처치도 기존 전적/숙련도/라운드 보상 규칙으로 중복 없이 저장합니다. LAN 서버와 브라우저 워커가 같은 장비 규칙을 사용하고, 이전 생명·장비·라운드의 지연 요청과 중복 G 요청은 거부합니다. 프로토콜 13이므로 구버전 LAN 서버는 진행 중인 방을 마친 후 재시작하고 클라이언트도 새로고침해야 합니다.

방 생성 시 목표 **1–200킬 / 제한 시간 1–60분**을 선택할 수 있으며 기본은 20킬/5분입니다. 해당 방 참가자 모두에게 적용하고 재경기에도 유지합니다. 저격총은 정조준 발사 직후 줌을 풀며, 클릭 순간의 조준각/ADS를 서버가 보존하므로 반동·줌 해제 입력이 같은 틱의 탄착점을 바꾸지 않습니다. 빠른 단발 입력과 최대 200ms 이내의 표시 지연을 보정하고, 어깨·발 쪽 몸통 판정의 빈틈도 보강했습니다. 스폰 보호는 유지하되 청색 링/명중 표시로 구분합니다.

정지 정조준 < 걷기 < 달리기 < 공중 순으로 실제 탄 퍼짐이 커집니다. 달리면서 사격해도 달리기 상태가 정확도 계산에서 사라지지 않습니다. 라이플은 더 큰 수직 시점 반동과 누적 탄 퍼짐을 사용하며 짧게 끊어 쏘면 회복됩니다. 반동 시점은 서버로 전송하는 조준각과 같습니다. 조준선은 전체 확대 대신 주변 선만 벌어지며, 점프·반동·확대 중에도 중심점은 화면의 정확한 중앙에 고정됩니다.

**SR–1 / AWP / Barrett M82**는 노줌 탄 퍼짐을 크게 높였으며, 이동 중에는 확대해도 정확도가 크게 떨어집니다. 걷기보다 달리기·공중 사격의 불이익이 더 크므로 정확한 저격에는 정지·확대가 필요합니다. 정지 정조준의 기존 정밀도와 피해량·시점 반동은 유지하며, 다른 17종 무기의 탄 퍼짐은 바꾸지 않습니다. 서버/LAN·1인 워커·조준선은 같은 공통 계산을 사용합니다.

몸통은 **최대 1.2배**, 팔은 어깨에서 손끝으로 갈수록 연속적으로 **1.2 → 0.5배**의 피해 배율을 적용합니다. 머리는 기존 무기별 헤드샷 피해/거리 감소를 유지하고, 다리의 기본 배율은 1배입니다. 팔·손의 캡슐 근사 판정과 몸통 중 먼저 맞은 부위를 사용하며, 팔이 몸통 앞을 가리면 팔 피해가 적용됩니다. 산탄도 탄알마다 부위·거리 배율을 계산한 뒤 합산합니다. 남녀/외형에 따른 차이는 없으며 지연 보정에는 당시 시선·무기·앉기 자세도 포함됩니다.

유효한 피해를 받으면 **1초 동안 이동속도가 30% 감소**합니다. 연속 피격은 종료 시간만 갱신하고 배율은 중첩하지 않습니다. 조준 감도·시점 회전·중력은 그대로이며 공중의 저장된 이동 방향도 유지합니다. 스폰 보호로 막힌 탄은 둔화를 주지 않고 사망/부활 시 효과를 초기화합니다. 히트마커는 중앙이 빈 대각선 4개에 **굵은 선·어두운 외곽선**을 겹쳐 밝고 어두운 배경 모두에서 보이도록 했습니다. 일반 명중은 흰색 38px/240ms, 헤드샷은 금색 42px/320ms, 스폰 보호 명중은 청색 방패 38px/220ms로 구분하며 표시 시간의 72%까지 완전한 밝기를 유지한 뒤 사라집니다.

발사로 생긴 일시적인 시점 반동은 마지막 발사 후 약 150ms부터 마우스로 조준한 방향으로 부드럽게 복귀합니다. 복귀 중 마우스를 움직이면 그 조준을 새 기준으로 유지하며, 단발·연사·프레임 지연 후에도 잔여 반동이 영구 누적되지 않습니다. 복귀 중에도 화면과 서버에 보내는 조준각은 동일합니다.

### 개인 무기 숙련도

각 무기로 누적 **50킬 → Lv1, 150킬 → Lv2, 350킬 → Lv3, 750킬 → Lv4**이며 이후 추가 필요 킬은 800·1,600…으로 두 배씩 늘어납니다. 킬마다 타이머 아래에 해당 무기 레벨과 다음 레벨 게이지를 표시하고, 상대의 사망 화면에도 처치자의 해당 무기 레벨을 표시합니다. **레벨은 숙련도 표시일 뿐 피해·체력 보너스는 없습니다.** 무기별 킬은 라운드 ID/단조 증가 원장으로 중복 저장을 막고, 중도 이탈해도 기록을 유지합니다. 기존 프로필의 과거 누적 킬을 임의로 무기별 배분하지 않으므로 기존 무기별 기록은 Lv0에서 시작합니다.

## 자동 프로필·전적·포인트

- 첫 진입 시 무작위 ID를 만들고 같은 저장소에 다시 접속하면 자동으로 인식합니다. **실제 호스트명, OS 계정명, MAC 주소 또는 IP를 식별자로 수집하지 않습니다.** 콜사인은 사용자가 선택한 게임 이름입니다.
- 웹/Vercel/일반 LAN 브라우저: **같은 사이트 주소(origin)의 같은 브라우저 로컬 저장소**에 저장합니다. 주소나 브라우저가 다르면 별도 프로필이며 브라우저 데이터를 지우면 사라집니다.
- Windows 패키지: 사용자 설정 폴더의 `LINKSHOT/profile.json`에 저장하며, 브라우저에도 임시 사본과 미완료 저장 요청을 보관합니다. 기존 파일이 손상되면 함부로 덮어쓰지 않고 브라우저 임시 저장으로 안내합니다.
- 킬/데스는 플레이 중에도 누적합니다. K/D는 `킬 / max(1, 데스)`, 킬 비율은 `킬 / (킬 + 데스)`입니다.
- **포인트는 라운드 종료 후에만** `완주 50 + 킬 × 20 + 승리 100 LP`로 지급합니다. 중도 이탈 시 전적은 남지만 종료 보상은 없습니다. 완료된 라운드 ID를 기록해 반복 스냅샷/새로고침에 중복 지급하지 않습니다.
- Windows 저장 API는 포인트 숫자 전체를 임의 덮어쓰는 요청 대신 라운드 정산/구매/장착 작업을 순서대로 처리합니다. 잔액 부족과 중복 구매를 검증합니다.
- **계정 로그인·클라우드 동기화·변조 방지형 경쟁 경제는 아닙니다.** 기기 소유자는 로컬 파일이나 브라우저 데이터를 직접 수정할 수 있습니다. 유료 재화나 공인 랭킹에 사용하려면 별도 인증 서버와 검증 저장소가 필요합니다.

둘 다 무료이며 기존 구매 외형 5종을 추가 구매 없이 공유합니다. 선택은 다음 출격에 적용되고 브라우저/선택적 PC 프로필에 저장됩니다. 예전 프로필은 남성으로 시작하며 LP·누적 전적·무기 숙련도·해금 내역은 유지합니다. 봇도 남녀를 섞어 사용합니다. **체력·이동·피격 범위는 동일하고 서 있는 1.8m/앉은 1.1m 판정은 성별에 따라 바뀌지 않습니다.**

### 1인칭 손과 파지 자세

둥근 도형을 이어 붙이던 손을 **남녀 인체 모델에서 추출한 실제 좌우 손 메시**로 바꿨습니다. 손가락 마디/엄지의 원래 본으로 방아쇠 손·전방 받침 손·권총 양손 파지를 만들고, 무기별 총열덮개/펌프 위치에 맞춰 배치합니다. 손목까지 이어지는 곡면 소매·커프스와 로컬 엔진의 원단/장갑 재질을 적용하며, 기본·정찰·복고 외형은 손끝 노출, 방호·우주 외형은 손 전체를 덮습니다. 산탄총의 받침 손은 실제 펌프 이동을 따라갑니다.

**모든 총과 나이프의 양팔**에 중립 손목과 직선 전완을 적용합니다. SMG/P90·산탄총·LMG·DMR·권총에 남아 있던 곡선 소매를 제거해 팔뚝이 고무관처럼 휘지 않습니다. 무기별 파지 위치/회전은 `public/weapon-grips.js`의 무기 로컬 손 고정점으로 관리하며, 반동·ADS·펌프와 손이 같은 좌표계에서 이동합니다. 소매는 손목으로 완만하게 좁아지고 넓은 FOV에서도 팔 시작점/팔꿈치를 화면 밖에 둡니다. 총의 조준점과 기존 방아쇠 손/권총 손바닥의 위치는 유지합니다.

참고한 방식: [Unreal Two Bone IK의 무기 파지·손 회전/관절 타깃](https://dev.epicgames.com/documentation/en-us/unreal-engine/two-bone-ik?application_version=4.27), [Unity Two Bone IK의 Target/Hint/회전 분리](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html), [FPS 무기 로컬 IK와 펌프 고정점](https://zaggoth.wordpress.com/author/zaggoth/). 다른 게임의 모델/애니메이션을 복제하거나 엔진 전체를 교체하지 않으며, 3인칭은 기존 2본 IK, 1인칭은 화면 밖 팔꿈치와 강체 전완을 사용합니다.

손과 총은 별도의 깊이 패스로 그려 **서로 뚫고 보이지 않으면서 가까운 벽에 잘리지 않게** 했습니다. 정조준 위치/FOV와 서버로 보내는 조준각·피해·피격 범위는 유지하고, 비조준 표시 위치는 양손이 덜 잘리도록 조정했습니다. 준비된 손 모양은 경기 단위로 공유해 매 프레임 손가락 스키닝을 계산하지 않으며, 경기 종료 때 메시/재질을 해제합니다.

## `~/engine` 애셋 제작

맵·스킨·캐릭터 콘셉트와 의복 재질은 **`~/engine`의 로컬 ComfyUI + Animagine XL 4.0 Opt**로 생성합니다. 2D 엔진은 재질을 제작하며, 3D 인체 베이스는 별도 라이선스의 **Quaternius Universal Base Characters Standard(CC0)**입니다. 유료 Source 모델은 사용하지 않습니다. 지형·장비·의복 보강·IK/자세·효과는 프로젝트 코드로 제작합니다. 엔진이 꺼져 있어도 커밋된 GLB/PNG/WAV로 실행되며 빌드는 필요한 모델·소리까지 검증합니다.

총성은 **Tabasco의 CC0 실제 사격 녹음**에서 고립된 한 발만 추출하고 잡음 제거·필터링·정규화와 뒤따르는 반사음/기계음 억제를 거친 고정 샘플입니다. AK·M4의 한 샘플 안에 여러 격발이 섞이던 문제를 제거했습니다. 무기마다 매번 같은 파일/음높이를 사용하며 임의 변형이나 장전음 같은 합성 대체음을 재생하지 않습니다. 발사 예측과 서버 확인은 방아쇠 순번/탄 순번으로 매칭하므로 지연·중복 ACK가 같은 총성을 다시 재생하지 않습니다. 거리 감쇠/좌우 방향/실내 잔향과 동시 발음 제한·리미터를 적용합니다. 파일 출처/라이선스는 [`public/assets/THIRD_PARTY.md`](public/assets/THIRD_PARTY.md)와 소리 manifest에 기록되어 있습니다.

**SR–1 / AWP / Barrett M82**는 저음 몸체를 보강한 고정 단발 샘플과 각각 **1.65 / 1.95 / 2.20초**의 길고 확산되는 잔향을 사용합니다. 녹음 속 다음 격발이나 볼트 소리를 붙인 것이 아니라, 고립된 한 발에 저음·잔향을 가공한 것입니다. 같은 총은 매번 같은 파일과 재생 속도 1을 유지하며 다른 17종 총성은 바꾸지 않습니다.

발소리와 킬 확인음은 `public/sound-design.js`의 자체 합성 신호를 사용하며 추가 외부 샘플·음성 API가 필요하지 않습니다. 발소리는 좌우 발을 번갈아 재생하고 주변 소리는 거리·층 높이·카메라 방향을 반영합니다. 벽 뒤에서는 작고 둔탁하게 들리되 시야 밖이라는 이유로 완전히 사라지지는 않습니다. 청취 거리는 걷기 최대 26m·달리기 34m·앉기 14m이며 실제 음량은 거리와 자세에 따라 줄어듭니다. 보폭은 프레임 속도에 의존하지 않고, 발소리 동시 재생 수를 제한합니다. 킬 확인음은 본인의 확정 처치에만 나고 마지막 라운드 킬에도 재생되며, 빠른 연속킬에서는 앞선 잔향을 부드럽게 줄입니다. 모두 설정의 효과음 볼륨·음소거를 따릅니다.

발소리는 **약 120ms의 짧고 낮고 단단한 뒤꿈치→앞꿈치 ‘도각’ 접지음**입니다. 주된 접지 음정을 약 250Hz로 낮추고 날카로운 고음·잡음·좌우 발의 음정 차이를 줄였습니다. 걷기/달리기는 2600Hz, 앉기는 1900Hz 저역 통과 필터를 기본으로 쓰며 거리·엄폐에 따라 더 둔탁해집니다. 낮은 주파수의 잔여 편향도 제거해 긴 울림이나 끌리는 꼬리는 남기지 않습니다.

다른 캐릭터의 보폭은 서버/워커의 누적 지상 이동거리로 계산합니다. 20Hz 상태가 정지 순간에 도착하거나 보간 중 순간 속도가 0이 되어도 이미 걸은 보폭이 사라지지 않습니다. 짧은 정지는 350ms 동안 보폭을 유지하며 공중·사망·순간이동은 별도로 억제합니다. 주변 발소리의 과도한 거리/엄폐 이중 감쇠를 완화하되 앉기 소리는 여전히 조용하고 벽 뒤에서는 둔탁해집니다.

장전음은 전자음 대신 **zer0_sol의 CC0 실제 탄창·슬라이드·탄피 삽입·펌프 녹음**을 사용합니다. 로컬 ComfyUI의 오디오 볼륨/EQ 노드로 헤드룸과 선명도를 조정한 뒤, 20종 각각에 맞춰 탄창 교체·볼트·펌프·탄띠 동작과 배율/타이밍을 별도로 편집했습니다. 샘플 길이는 실제 무기 장전 시간과 같고 네트워크 지연이 있으면 해당 시점부터 재생하며, 사망·부활·장비 변경·취소에는 이전 장전음을 멈춥니다. 엔진은 제작 때만 사용하고 플레이/빌드에는 커밋된 WAV와 `reload-manifest.json`만 필요합니다.

브라우저 테스트는 macOS에 설치된 Google Chrome을 우선 사용합니다. 없으면 `npx playwright install chromium`으로 테스트용 Chromium을 설치하세요. 테스트 스크린샷은 `artifacts/`에 저장됩니다. 이동 회귀 테스트는 24개 발판의 대각선 계단 이동·가장자리·점프·천장 충돌과 여러 프레임 속도를 검사합니다. 공중 방향/가속/제동 차단과 LAN 패킷 속도 위조 방지, 지연된 스냅샷의 이륙 속도 보존도 검사합니다. 브라우저에서는 남녀 2종 × 외형 5종 × 무기 색상 6종의 신체/얼굴/의복, 남녀 1인칭 손과 20종 무기, 여성 선택 저장·워커 적용과 PC 저장 파일 복원을 확인합니다.

1인칭 손은 남녀 × 외형 5종 × 무기 20종의 200개 조합에서 해부학적 좌우 구분·손가락·정상 소매 면 방향·유한 좌표·깊이 판정을 확인합니다. 실제 브라우저 픽셀 비교로 벽 앞에서도 손/총이 유지되고 배경이 지워지지 않는지, 산탄총 펌프와 받침 손의 상대 위치가 유지되는지도 검사합니다. `node scripts/render-viewmodels.mjs`는 격리된 브라우저에서 무기별 비교 시트를 `artifacts/`에 저장합니다. `VIEWMODEL_CHARACTER=female`, `VIEWMODEL_POSE=ads`/`reload`/`grip`, `VIEWMODEL_TAG=review`로 대상을 바꿀 수 있습니다.

총몸은 20종 × 스킨 6종에서 연속 형상·총구의 실제 보어·열린 조준선·유한 좌표·공유 버퍼 수명을 검사합니다. FAMAS의 낮은 캐리 핸들/상부 시야는 실제 렌더 픽셀로 확인하고, 기본 소총과 FAMAS 모두 실제 우클릭 ADS·앉기·반동 중 조준 정렬을 검증합니다.

E 선택 후 부활 이동은 LAN 공통 시뮬레이션과 실제 1인 플레이 워커 양쪽에서 검사합니다. 조준선은 일반/점프/반동/정조준, FOV 65/105와 홀수 해상도에서도 중심 오차 0.01 CSS px 미만을 검사합니다. 건물 34개의 계단 경로와 온실 관리교의 양방향 이동·봇 상하행·하부 통로, 야시장의 꺾인 골목/광장 동선·노점 엄폐·천막 충돌을 검사합니다. 새 두 전장의 비직사각형 영역·모든 지상 스폰의 중앙 연결 경로와 실제 브라우저 렌더 배치 수·충돌물 연결·장면 자원 해제도 확인합니다. 고정 총성 20개와 후속 격발 파형 검사, 3점사·무기별 실제 피해/탄창·난이도별 AI·8인 입장·혈흔/시체 정리도 회귀 테스트에 포함됩니다. 자연 엄폐 스폰의 지지/출구·사선 차폐, 사망 후 발사 차단, 킬 효과·숙련도, 웹/네이티브 영구 해금과 기존 프로필 호환성도 검사합니다.

우클릭 조준 상태에서 라운드가 끝나 마우스 잠금이 풀려도 결과표/버튼 위에 브라우저 메뉴가 뜨지 않도록 게임 화면 전체에서 우클릭 기본 동작을 차단합니다. 정지·사망·결과 화면에도 적용하며, 조준 해제·재경기 왼쪽 클릭과 로비로 나간 뒤의 정상 페이지 우클릭은 실제 브라우저에서 검증합니다.

발소리는 30–144Hz 보폭·좌우 방향·거리/엄폐 감쇠·사망/공중 억제와 낮은 접지 음정/짧은 꼬리를 검사하며 실제 브라우저에서 내 이동과 원격 이동 모두 소리를 내는지 확인합니다. 킬/연속킬/헤드샷 확인음의 구분·중복 방지·음소거·동시 발음 제한과 저격총 저음/긴 감쇠 파형도 검사합니다. 저격총 3종의 노줌·이동 탄 퍼짐은 고정 시드의 실제 서버 사격 명중률로 검증하며, 110m 정지 정조준 명중과 클릭 순간 조준각/ADS 보존도 유지합니다.

부위별 피해·회전/앉기·산탄별 배율·과거 팔 자세·1초 둔화/중첩 방지와 히트마커 중앙 정렬·크기·외곽선·밝기 유지 시간도 검사합니다. 장전은 20종 모두 마지막 탄과 같은 틱에 시작하는지, 녹음 샘플 20개가 서로 다르고 실제 장전 시간과 일치하는지, 취소된 장전음이 늦게 재생되지 않는지 검사합니다.

### 프레임 지연 진단

시체 소멸이 시작될 때 불투명→반투명 셰이더가 처음 컴파일되어 생기던 큰 멈춤을 줄였습니다. 교전 전 그래픽 준비 화면에서 무기·캐릭터·반투명 시체·피격 효과의 셰이더와 버퍼를 미리 준비하고, 시체는 처음부터 같은 투명 모드로 유지합니다. 캐릭터의 변경되지 않는 메시 버퍼도 경기 단위로 공유하고 경기 종료 때 한 번 해제합니다.

그래픽 준비 중 다른 참가자가 나가거나 장비가 바뀌면 해당 재질의 해제를 셰이더 컴파일 완료 뒤로 미룹니다. 준비 도중 본인이 로비로 나가도 GPU 자원은 컴파일이 끝난 뒤 안전하게 정리하므로, 드라이버가 아직 참조하는 프로그램을 먼저 지워 로딩이 중단되는 문제를 방지합니다.

`BENCH_SECONDS=12 BENCH_MAP=foundry node scripts/benchmark-game.mjs`는 사용자 브라우저/LAN 방과 분리된 헤드리스 7봇 환경을 측정합니다. 프레임/렌더/스냅샷/시체 생성 지표와 CPU 프로필을 공개 제외 경로 `artifacts/`에 저장하고 브라우저·테스트 서버를 종료합니다. 개발 장비의 개선 전 샘플에서 시체 소멸 시 약 1.25초의 렌더 지연을 확인했으며 사전 준비 후 재측정에서 해당 지연은 재현되지 않았습니다. 수치는 하드웨어·장면에 따라 달라지며 모든 종류의 지연이 사라진다는 보장은 아닙니다.

실행 중인 `npm start`는 공통 서버 모듈을 메모리에 유지하므로, 서버 규칙/맵을 업데이트했다면 **진행 중인 방을 종료한 뒤 서버를 재시작하고 브라우저도 새로고침**하세요. 새 클라이언트가 이전 프로토콜의 방에 진입하려 하면 재시작 안내를 표시해 오래된 충돌/사격 규칙과 섞이지 않게 합니다. 브라우저 프로필/포인트는 서버 재시작으로 삭제되지 않습니다.

- `npm run security:check`는 **추적 중인 파일 + ignore되지 않은 파일**을 검사합니다. 아직 Git 저장소가 없어도 임시 인덱스로 공개 후보를 계산하며, 프로젝트에 Git 저장소를 만들거나 스테이징하지 않습니다.
- 기본 자격증명/개인정보 규칙 및 PNG 텍스트 메타데이터 검사가 포함됩니다. `gitleaks`가 PATH 또는 `.toolchain/gitleaks/`에 있으면 기본 제공 규칙으로 추가 검사합니다. 출력에는 매칭된 비밀값을 표시하지 않습니다.
- `.env*`, 인증서/비밀키, 로컬 패키지 인증 설정, 개발 도구, 로그, 스크린샷 및 빌드 산출물은 `.gitignore`로 제외합니다. **ignore는 이미 커밋된 파일을 지우지 않으므로** 업로드 전에 `git status --short`와 `git diff --cached`도 확인하세요. 검사 명령은 강제로 추적된 민감 파일도 거부합니다.
- Windows ZIP은 Git에 커밋하지 말고 필요하면 GitHub Releases 등에 별도 배포하세요. 게임 이미지는 `public/assets/`에 포함된 공개용 생성 이미지입니다.
- 현재 실행 중 LAN 주소를 표시하는 기능은 정상 동작이며, 공개 문서용 스크린샷에서는 실제 주소를 예시 주소로 치환합니다.
- 커밋 작성자 이름/이메일도 Git 기록에 공개됩니다. 개인 이메일을 숨기려면 커밋 전에 GitHub의 noreply 이메일 설정을 확인하세요.
- `profile.json`, `profiles.json`, `linkshot-profile*.json`, `data/`, `.linkshot/`는 개인 게임 기록이므로 Git에서 제외합니다. Windows 저장 파일과 사용자 ID는 배포 ZIP이나 소스에 포함하지 않습니다.

## 구조와 범위

```text
server/    HTTP, WebSocket, 방·봇·전투 시뮬레이션
shared/    공통 맵·무기·스킨 카탈로그, 물리, 서버/워커 공통 시뮬레이션
public/    로비, Three.js 클라이언트, 생성 이미지, UI/효과음
scripts/   정적 빌드, 미리보기, Windows 패키징, ~/engine 이미지 생성
tests/     Node 테스트와 Playwright 브라우저 테스트
```

LAN 개발은 별도 번들링 없이 `npm start` 하나로 HTTP와 WebSocket이 같은 포트를 사용합니다. 정적 배포용 `npm run build`는 브라우저 파일·공통 모듈·Three.js를 `dist/`에 모으고 실행 방식을 1인 플레이로 설정합니다. 서버 또는 워커는 60Hz 시뮬레이션·20Hz 스냅샷, 클라이언트는 이동 예측과 상대 위치 보간을 사용합니다. 진행 중인 방/라운드는 메모리에 보관되지만 누적 전적/포인트/구매 외형은 기기별 저장소에 유지됩니다. Windows EXE는 정적 사이트와 로컬 프로필 API를 내장한 Go 표준 라이브러리 런처입니다.

초기 프로토타입 범위이며, 인터넷 매치메이킹·온라인 계정/클라우드 전적·팀전·음성 채팅·모바일 조작·정교한 랙 보정/안티치트는 포함하지 않습니다.
