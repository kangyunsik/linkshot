# LINKSHOT · 링크샷

**6개 전장 · 19종 무기 · 무기 색상 6종 · 캐릭터 외형 5종**을 제공하는 브라우저 3D FPS 프로토타입입니다. 기기별 누적 전적과 포인트, 외형 상점이 포함되어 있으며 두 실행 방식을 지원합니다.

- **1인 플레이 / Vercel / Windows 패키지:** 봇과 전투 판정이 브라우저의 Web Worker에서 실행됩니다. 게임 서버나 Node.js 설치 없이 플레이합니다.
- **LAN 멀티플레이:** `npm start`로 Node.js 서버를 열고 같은 네트워크에서 최대 8명이 플레이합니다. 서버에서 이동·충돌·사격·피격·점수를 판정합니다.

계정, 유료 API, 외부 게임 서버가 필요하지 않습니다. `~/engine`은 개발 시 이미지 제작에만 사용하며 플레이할 때는 필요하지 않습니다.

## 비개발자 친구에게 전달하기 (Windows 1인 플레이)

### 가장 간단한 방법: Vercel 링크

Vercel에 배포한 주소를 보내면 친구는 최신 **Edge 또는 Chrome**에서 주소를 열기만 하면 됩니다. Node.js/npm/Python을 설치할 필요가 없습니다. Vercel 배포 절차는 아래를 참고하세요.

### 파일로 보내기: Windows 포터블 ZIP

제작하는 컴퓨터에서 한 번 실행합니다.

```sh
npm install
npm run setup:packaging   # 최초 1회. 프로젝트 전용 Go 컴파일러 다운로드 + SHA-256 검증
npm run package:windows   # 1인 플레이 빌드 → Windows x64 EXE → ZIP
```

친구에게 **`release/LINKSHOT-Windows-x64.zip`만 전달**하면 됩니다.

1. ZIP을 **압축 해제**합니다.
2. 안에 있는 **`LINKSHOT.exe`를 더블클릭**합니다.
3. 기본 브라우저가 열리면 전장·무기·스킨을 고르고 **연습전 시작 → 교전 시작**을 누릅니다.
4. 게임 중에는 작은 실행 창을 열어 두고, 끝나면 그 창을 닫습니다.

실행 파일 안에 게임과 정적 웹서버가 포함되어 있습니다. **설치, 관리자 권한, 인터넷, Node.js, Python, Go가 친구 컴퓨터에 필요하지 않습니다.** 브라우저 및 WebGL 지원은 필요합니다. 서버는 `127.0.0.1`에만 열리며 LAN/인터넷으로 게임을 공개하지 않습니다. 기본 포트 `27007`이 사용 중이면 빈 포트를 자동 선택합니다. 브라우저가 자동으로 열리지 않으면 실행 창에 나온 URL을 직접 여세요.

전적/포인트/구매 외형은 **현재 Windows 사용자의 설정 폴더에 있는 `LINKSHOT/profile.json`**에 저장됩니다. 일반적인 Windows 환경에서는 `%APPDATA%\LINKSHOT\profile.json`입니다. 새 ZIP으로 교체하거나 브라우저 저장소를 지워도 이 파일은 유지됩니다. 실행 파일이 이미 켜져 있으면 가능한 경우 기존 로컬 실행 창을 재사용합니다. 저장 API는 로컬·동일 출처 요청만 허용하고, 파일은 임시 저장 후 교체합니다.

> Windows 10/11 x64 대상입니다. ARM64 패키지가 필요하면 `npm run package:windows -- --arm64`를 사용하세요. 빌드 컴퓨터에는 Go가 필요하며, 위 자동 설치는 macOS/Linux에서 시스템을 변경하지 않고 `.toolchain/`에만 설치합니다. Windows에서 빌드할 때는 [Go](https://go.dev/dl/)를 설치하세요. 실행 파일은 서명되지 않은 개인 테스트용이므로 SmartScreen/보안 소프트웨어의 확인 또는 차단이 있을 수 있습니다. 출처 및 `release/*.sha256`을 확인하고 보안 정책을 따르세요. 폭넓게 배포할 때는 코드 서명을 고려하거나 Vercel 링크를 사용하세요. Mac에서 교차 빌드한 파일의 실제 Windows 실행은 별도 확인이 필요합니다.

## 1인 플레이 빌드와 Vercel 배포

빌드하는 컴퓨터에만 Node.js 22 이상이 필요합니다.

```sh
npm install
npm run build        # 정적 1인 플레이 사이트 → dist/
npm run preview      # http://localhost:4173
```

`dist/`는 정적 웹사이트입니다. 플레이 중 Node.js를 실행할 필요가 없으며, Vercel/Nginx/Apache 등 정적 호스팅에서 실행합니다. Node 없이 로컬 확인을 하려면 Python이 있는 컴퓨터에서 `python3 -m http.server 8000 --directory dist`도 가능합니다. ES 모듈과 Web Worker 때문에 `dist/index.html` 더블클릭(`file://`)은 지원하지 않습니다. Windows 친구에게는 위 EXE 또는 Vercel 주소를 사용하세요.

**GitHub Actions는 Vercel 배포에 필요하지 않습니다.**

1. 이 프로젝트를 GitHub 저장소에 올립니다. `public/assets/`의 생성 이미지도 포함하고, `node_modules/`, `.toolchain/`, `artifacts/`, `release/`, `dist/`는 올리지 않습니다.
2. Vercel에서 **Add New → Project → 해당 GitHub 저장소 Import**를 선택합니다.
3. Framework는 **Other**, Build Command는 **`npm run build`**, Output Directory는 **`dist`**입니다. 포함된 `vercel.json`이 이 값을 설정합니다.
4. **Deploy**를 누르고 생성된 HTTPS 주소를 공유합니다. 이후 연결한 브랜치에 push하면 자동 배포됩니다.

이 배포에는 `/api`나 WebSocket 서버가 필요하지 않습니다. 1인 플레이는 `shared/simulation.js`를 브라우저 워커에서 실행합니다. LAN 버전의 메모리 기반 방 서버를 Vercel Functions에 그대로 올리는 구성이 아닙니다. Actions는 선택적으로 테스트 CI에만 사용할 수 있습니다. GitHub 업로드와 Vercel 배포는 별개이며, 사이트 공개는 Vercel에서 이 저장소를 Import한 뒤 진행합니다.

## LAN 멀티플레이 실행

Node.js 22 이상이 필요합니다.

```sh
npm install
npm start
```

- 이 컴퓨터: **http://localhost:3000**
- 친구: 터미널 또는 로비에 표시되는 **http://192.168.x.x:3000** 같은 LAN 주소
- 서버는 기본적으로 `0.0.0.0:3000`에서 수신합니다. 포트 변경: `PORT=8080 npm start`
- 개발 중 자동 재시작: `npm run dev` (재시작하면 진행 중인 방은 초기화됩니다.)

### 친구와 플레이

1. 서버 컴퓨터와 같은 Wi-Fi/유선 LAN에 접속합니다.
2. 한 명이 **LAN 대전 → 방 만들고 출격**을 누릅니다.
3. 게임 메뉴에서 **친구 초대 링크 복사**를 누르고 친구에게 전달합니다. 친구가 링크를 열면 같은 방으로 바로 참가합니다.
4. 또는 같은 LAN 주소로 접속한 뒤 **5자리 방 코드**를 입력하거나 **열린 방 보기**에서 참가합니다.
5. 각자 **교전 시작**을 클릭하면 마우스가 잠기고 조작을 시작합니다. `Esc`로 커서를 해제합니다.

> 접속되지 않으면 macOS의 로컬 네트워크 권한 및 방화벽에서 Node.js를 허용하세요. 게스트 Wi-Fi의 AP/client isolation은 기기 간 접속을 차단할 수 있습니다. 친구에게 `localhost`를 공유하면 안 됩니다. 인터넷 공개 서버를 전제로 만든 보안/인증 시스템은 없으므로 공유기 포트포워딩 없이 신뢰할 수 있는 LAN에서 사용하세요.

## 구현된 내용

- 6개 독립 레이아웃, 충돌·점프·엄폐물·그림자, 맵별 봇 경로 탐색과 미니맵
- 모든 전장에 실제로 올라설 수 있는 **계단식 발판 4개와 추가 엄폐물 12개**를 배치했습니다. 낮은 계단은 걸어서 오르내리고, 1.8m 발판은 계단이 없는 면에서도 점프로 올라갈 수 있습니다. 가장자리 지지/착지는 측면 충돌과 같은 범위를 사용하며, 발판 밖으로 벗어나면 중력이 적용됩니다. 높은 위치는 실제 사격 시야에도 반영됩니다.
- `C` 또는 `Ctrl`을 누르는 동안 앉기: 낮아지는 시점·머리/몸통 피격 범위, 느린 이동과 조용한 발소리, 낮은 엄폐 뒤 숨기. 머리 위 공간이 부족하면 자동으로 앉은 자세를 유지합니다.
- 최대 8명 개인전, 5자리 방 코드, 여러 방, 초대 링크, 방장 자동 위임
- 최대 8명 LAN 대전, 0–7개 연습 봇(사람이 참가하면 봇이 비워짐), 초급/중급/고급 선택. 정적 배포는 1인+최대 7봇입니다.
- 봇끼리도 싸우는 개인전 AI: 인간 우선 타기팅 없음, 0.6–1.0초 반응 지연, 약 63°/초의 느린 몸 회전, 지연된 위치 추적과 조준 오차
- 초급 봇의 기본 자동소총 사격은 명중률이 낮은 짧은 2–3발 연사를 사용하며, 탄 사이 최소 0.45초와 연사 후 0.65–1.0초 휴식이 있습니다. 고유 3점사 무기의 점사 내부 주기는 무기 설정을 따릅니다. 봇 난이도가 플레이어의 무기 피해량이나 마우스 감도를 바꾸지는 않습니다.
- 위 봇 설정은 **초급(기존 반응/조준 설정)**입니다. 중급은 반응 350–550ms·최소 탄 간격 300ms, 고급은 반응 180–300ms·최소 탄 간격 180ms이며 무기 자체의 발사 주기보다 빨라지지 않습니다. 봇은 소총·SMG·산탄총·저격총·권총·LMG·DMR을 나눠 들고 플레이어와 동일한 무기별 피해/거리 감소/헤드샷을 적용합니다. 기존 15 고정 피해 보정은 제거했습니다. 체력은 모두 100입니다.
- 6개 전장에 **6–9m 높이의 진입 가능한 건물 25개와 추가 엄폐벽 48개**가 있습니다. 실제 실내 계단·중간층·옥상·출입문을 사용하며, 창이 없는 막힌 패널/계단실과 열린 사격창을 섞었습니다. 창과 문은 보이는 대로 이동/사격 판정에도 반영됩니다.
- 돌격소총·기관단총·산탄총·저격소총·권총·경기관총·지정사수소총, 무기별 탄창/연사/재장전/반동/효과음, 헤드샷과 거리별 피해량
- 무기별 걷기/달리기 속도와 정조준 이동 페널티: 권총/기관단총은 가볍고 경기관총/저격총은 무겁습니다. 라이플 정조준은 실제 사격과 같은 시점/각도를 사용하며, 화면 반동 때문에 조준점과 탄착점이 어긋나지 않습니다.
- 산탄총 8개 산탄의 개별 피격 판정, 저격 스코프, 무기별 독립 탄창, 재장전 취소 및 교체 지연
- 무기와 캐릭터 공통 스킨 6종, 실제 3D 장비 미리보기, 시작 장비/전장/스킨 브라우저 저장
- 서버 권위 이동 및 피격 판정, 사격 속도 제한, 오래된 입력 자동 해제
- 3초 리스폰, 1.5초 스폰 보호 (사격하면 해제)
- 5분 또는 20킬 라운드, 점수판, 킬 피드, 방장 재경기
- 미니맵 (시야 내 상대만 표시), 로컬 합성 효과음, 감도·FOV·음량·그래픽 설정
- 피격 시 붉은 화면 효과와 **8방향 경고 표시**가 약 1.1초간 공격 방향을 알려줍니다. 시선을 돌리면 표시도 회전하고, 여러 공격자의 최근 피격 방향을 최대 4개까지 표시합니다.
- 중앙 방향 문구는 표시하지 않습니다. 피격에는 짧은 혈흔 입자/표면 흔적, 사망에는 쓰러짐과 최대 10초 유지되는 시체가 나타납니다. 시체는 최대 8개, 혈흔은 제한된 개수만 유지하며 이동·사격 판정을 막지 않습니다.
- WebSocket 연결 복구 (진행 중인 방 자동 재참가는 하지 않음)
- 기기별 자동 ID, 누적 킬/데스/KD·킬 비율·완료 경기·승리·포인트 자동 저장과 메인 화면 표시
- 라운드 종료 때 한 번만 지급하는 보상, 포인트로 구매/장착하는 능력치 없는 캐릭터 외형 상점

브라우저는 키보드와 마우스가 있는 최신 데스크톱 Chrome/Edge/Firefox/Safari 및 WebGL 지원이 필요합니다. 모바일 UI는 반응형이지만 터치 FPS 조작은 구현하지 않았습니다.

| 조작 | 기능 |
| --- | --- |
| WASD | 이동 |
| 마우스 / 좌클릭 | 조준 / 사격 |
| 우클릭 | 정조준 |
| E (사망 중) | 19종 목록에서 다음 부활 무기 선택 · 처음 10종은 1–9, 0 · 나머지는 클릭 |
| C / Ctrl 누르기 | 앉기 (브라우저에서는 C 권장) |
| Shift / Space | 달리기 / 점프 |
| R / Tab | 재장전 / 점수판 |
| Esc / F | 메뉴 및 마우스 해제 / 전체 화면 |

산탄총/저격총/권총/지정사수소총은 클릭할 때마다 한 발씩 발사합니다. **생존 중 숫자키·휠·임의 네트워크 입력으로 무기를 바꿀 수 없습니다.** 사망 후 E로 선택하면 다음 부활부터 적용하고, 선택 대기는 사망 후 최대 15초입니다. 선택 후 마우스 잠금을 복원하며 브라우저가 거절하면 재개 버튼을 표시합니다. 달리기·공중에서는 새로 앉을 수 없고, 낮은 천장 아래의 강제 앉기는 안전하게 유지합니다.

방 생성 시 목표 **1–200킬 / 제한 시간 1–60분**을 선택할 수 있으며 기본은 20킬/5분입니다. 해당 방 참가자 모두에게 적용하고 재경기에도 유지합니다. 저격총은 정조준 발사 직후 줌을 풀며, 클릭 순간의 조준각/ADS를 서버가 보존하므로 반동·줌 해제 입력이 같은 틱의 탄착점을 바꾸지 않습니다. 빠른 단발 입력과 최대 200ms 이내의 표시 지연을 보정하고, 어깨·발 쪽 몸통 판정의 빈틈도 보강했습니다. 스폰 보호는 유지하되 청색 링/명중 표시로 구분합니다.

정지 정조준 < 걷기 < 달리기 < 공중 순으로 실제 탄 퍼짐이 커집니다. 달리면서 사격해도 달리기 상태가 정확도 계산에서 사라지지 않습니다. 라이플은 더 큰 수직 시점 반동과 누적 탄 퍼짐을 사용하며 짧게 끊어 쏘면 회복됩니다. 반동 시점은 서버로 전송하는 조준각과 같습니다. 조준선은 전체 확대 대신 주변 선만 벌어지며, 점프·반동·확대 중에도 중심점은 화면의 정확한 중앙에 고정됩니다.

발사로 생긴 일시적인 시점 반동은 마지막 발사 후 약 150ms부터 마우스로 조준한 방향으로 부드럽게 복귀합니다. 복귀 중 마우스를 움직이면 그 조준을 새 기준으로 유지하며, 단발·연사·프레임 지연 후에도 잔여 반동이 영구 누적되지 않습니다. 복귀 중에도 화면과 서버에 보내는 조준각은 동일합니다.

## 자동 프로필·전적·포인트

- 첫 진입 시 무작위 ID를 만들고 같은 저장소에 다시 접속하면 자동으로 인식합니다. **실제 호스트명, OS 계정명, MAC 주소 또는 IP를 식별자로 수집하지 않습니다.** 콜사인은 사용자가 선택한 게임 이름입니다.
- 웹/Vercel/일반 LAN 브라우저: **같은 사이트 주소(origin)의 같은 브라우저 로컬 저장소**에 저장합니다. 주소나 브라우저가 다르면 별도 프로필이며 브라우저 데이터를 지우면 사라집니다.
- Windows 패키지: 사용자 설정 폴더의 `LINKSHOT/profile.json`에 저장하며, 브라우저에도 임시 사본과 미완료 저장 요청을 보관합니다. 기존 파일이 손상되면 함부로 덮어쓰지 않고 브라우저 임시 저장으로 안내합니다.
- 킬/데스는 플레이 중에도 누적합니다. K/D는 `킬 / max(1, 데스)`, 킬 비율은 `킬 / (킬 + 데스)`입니다.
- **포인트는 라운드 종료 후에만** `완주 50 + 킬 × 20 + 승리 100 LP`로 지급합니다. 중도 이탈 시 전적은 남지만 종료 보상은 없습니다. 완료된 라운드 ID를 기록해 반복 스냅샷/새로고침에 중복 지급하지 않습니다.
- Windows 저장 API는 포인트 숫자 전체를 임의 덮어쓰는 요청 대신 라운드 정산/구매/장착 작업을 순서대로 처리합니다. 잔액 부족과 중복 구매를 검증합니다.
- **계정 로그인·클라우드 동기화·변조 방지형 경쟁 경제는 아닙니다.** 기기 소유자는 로컬 파일이나 브라우저 데이터를 직접 수정할 수 있습니다. 유료 재화나 공인 랭킹에 사용하려면 별도 인증 서버와 검증 저장소가 필요합니다.

## `~/engine` 애셋 제작

맵·스킨·캐릭터 콘셉트와 의복 재질은 **`~/engine`의 로컬 ComfyUI + Animagine XL 4.0 Opt**로 생성합니다. 2D 엔진은 재질을 제작하며, 3D 인체 베이스는 별도 라이선스의 **Quaternius Universal Base Characters Standard(CC0)**입니다. 유료 Source 모델은 사용하지 않습니다. 지형·장비·의복 보강·IK/자세·효과는 프로젝트 코드로 제작합니다. 엔진이 꺼져 있어도 커밋된 GLB/PNG/WAV로 실행되며 빌드는 필요한 모델·소리까지 검증합니다.

총성은 **Tabasco의 CC0 실제 사격 녹음**에서 발사음만 추출하고 잡음 제거·필터링·정규화를 거친 고정 샘플입니다. 무기마다 매번 같은 파일/음높이를 사용하며 임의 변형이나 장전음 같은 합성 대체음을 재생하지 않습니다. 거리 감쇠/좌우 방향/실내 잔향과 동시 발음 제한·리미터를 적용합니다. 저격총의 마지막 발 자동 재장전은 발사 주기 이후에만 시작합니다. 파일 출처/라이선스는 [`public/assets/THIRD_PARTY.md`](public/assets/THIRD_PARTY.md)와 소리 manifest에 기록되어 있습니다.

```sh
# ~/engine/server-process.json의 URL 사용. 기존 이미지는 유지합니다.
npm run assets:generate

# 재생성 또는 다른 로컬 엔진 주소
npm run assets:generate -- --force
COMFY_URL=http://127.0.0.1:18188 npm run assets:generate

# 전장/재질은 유지하고 캐릭터 콘셉트 5장만 다시 생성
npm run assets:generate -- --outfits --force
# 특정 외형만 다시 생성 (쉼표로 여러 ID 지정 가능)
npm run assets:generate -- --outfit=runner --force
```

- 엔진 경로 변경: `ART_ENGINE_DIR=/path/to/engine`
- 프롬프트/시드/모델 출처: `public/assets/asset-manifest.json`
- 재현 가능한 API 워크플로: 생성 시 `artifacts/workflows/`에 저장
- 모델 라이선스: **CreativeML Open RAIL++-M** — [모델 카드](https://huggingface.co/cagliostrolab/animagine-xl-4.0). 생성물 배포 시 모델의 사용 제한과 별도 권리 문제를 확인하세요.
- 기존 엔진의 출력 디렉터리를 변경하지 않으며 PreviewImage 결과를 이 프로젝트로 가져옵니다.
- 재생성 이미지는 무시되는 `artifacts/asset-staging/`에 먼저 쓴 뒤 교체하므로 생성 중인 파일이 웹 화면에 노출되지 않습니다.


브라우저 테스트는 macOS에 설치된 Google Chrome을 우선 사용합니다. 없으면 `npx playwright install chromium`으로 테스트용 Chromium을 설치하세요. 테스트 스크린샷은 `artifacts/`에 저장됩니다. 이동 회귀 테스트는 24개 발판의 대각선 계단 이동·가장자리·점프·천장 충돌과 여러 프레임 속도를 검사합니다. 브라우저에서는 지연된 스냅샷에도 높은 발판/점프 예측이 유지되는지, 외형 5종 × 무기 색상 6종 및 1인칭 19종 무기 모두 인간형 모델을 유지하는지 확인합니다.

E 선택 후 부활 이동은 LAN 공통 시뮬레이션과 실제 1인 플레이 워커 양쪽에서 검사합니다. 조준선은 일반/점프/반동/정조준, FOV 65/105와 홀수 해상도에서도 중심 오차 0.01 CSS px 미만을 검사합니다. 건물 25개의 계단 경로, 고정 총성 19개, 3점사·무기별 실제 피해/탄창·난이도별 AI·8인 입장·혈흔/시체 정리도 회귀 테스트에 포함됩니다.

실행 중인 `npm start`는 공통 서버 모듈을 메모리에 유지하므로, 서버 규칙/맵을 업데이트했다면 **진행 중인 방을 종료한 뒤 서버를 재시작하고 브라우저도 새로고침**하세요. 새 클라이언트가 이전 프로토콜의 방에 진입하려 하면 재시작 안내를 표시해 오래된 충돌/사격 규칙과 섞이지 않게 합니다. 브라우저 프로필/포인트는 서버 재시작으로 삭제되지 않습니다.

## 공개 Git 업로드 전 보안 확인

- 검사 결과와 범위: [`SECURITY_REVIEW.md`](SECURITY_REVIEW.md)
- `npm run security:check`는 **추적 중인 파일 + ignore되지 않은 파일**을 검사합니다. 아직 Git 저장소가 없어도 임시 인덱스로 공개 후보를 계산하며, 프로젝트에 Git 저장소를 만들거나 스테이징하지 않습니다.
- 기본 자격증명/개인정보 규칙 및 PNG 텍스트 메타데이터 검사가 포함됩니다. `gitleaks`가 PATH 또는 `.toolchain/gitleaks/`에 있으면 기본 제공 규칙으로 추가 검사합니다. 출력에는 매칭된 비밀값을 표시하지 않습니다.
- `.env*`, 인증서/비밀키, 로컬 패키지 인증 설정, 개발 도구, 로그, 스크린샷 및 빌드 산출물은 `.gitignore`로 제외합니다. **ignore는 이미 커밋된 파일을 지우지 않으므로** 업로드 전에 `git status --short`와 `git diff --cached`도 확인하세요. 검사 명령은 강제로 추적된 민감 파일도 거부합니다.
- Windows ZIP은 Git에 커밋하지 말고 필요하면 GitHub Releases 등에 별도 배포하세요. 게임 이미지는 `public/assets/`에 포함된 공개용 생성 이미지입니다.
- 현재 실행 중 LAN 주소를 표시하는 기능은 정상 동작이며, 공개 문서용 스크린샷에서는 실제 주소를 예시 주소로 치환합니다.
- 커밋 작성자 이름/이메일도 Git 기록에 공개됩니다. 개인 이메일을 숨기려면 커밋 전에 GitHub의 noreply 이메일 설정을 확인하세요.
- `profile.json`, `profiles.json`, `linkshot-profile*.json`, `data/`, `.linkshot/`는 개인 게임 기록이므로 Git에서 제외합니다. Windows 저장 파일과 사용자 ID는 배포 ZIP이나 소스에 포함하지 않습니다.

## 구조와 범위

```text
server/    HTTP, WebSocket, 방·봇·전투 시뮬레이션
shared/    공통 맵·무기·스킨 카탈로그, 물리, 서버/워커 공통 시뮬레이션
public/    로비, Three.js 클라이언트, 생성 이미지, UI/효과음
scripts/   정적 빌드, 미리보기, Windows 패키징, ~/engine 이미지 생성
tests/     Node 테스트와 Playwright 브라우저 테스트
```

LAN 개발은 별도 번들링 없이 `npm start` 하나로 HTTP와 WebSocket이 같은 포트를 사용합니다. 정적 배포용 `npm run build`는 브라우저 파일·공통 모듈·Three.js를 `dist/`에 모으고 실행 방식을 1인 플레이로 설정합니다. 서버 또는 워커는 60Hz 시뮬레이션·20Hz 스냅샷, 클라이언트는 이동 예측과 상대 위치 보간을 사용합니다. 진행 중인 방/라운드는 메모리에 보관되지만 누적 전적/포인트/구매 외형은 기기별 저장소에 유지됩니다. Windows EXE는 정적 사이트와 로컬 프로필 API를 내장한 Go 표준 라이브러리 런처입니다.

초기 프로토타입 범위이며, 인터넷 매치메이킹·온라인 계정/클라우드 전적·팀전·음성 채팅·모바일 조작·정교한 랙 보정/안티치트는 포함하지 않습니다.
