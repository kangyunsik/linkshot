# LINKSHOT · 링크샷

**12개 전장 · 4개 교전 규칙 · 23종 무기 · 총기 Lv.5 소음기 · 무기 색상 6종 · 오퍼레이터 5명 · 전투복 5종**을 제공하는 브라우저 3D FPS 프로토타입입니다. 모드별 랭크와 전적, 무기 숙련도, 영구 무기 해금·외형 상점이 포함되어 있습니다.

- **1인 플레이 / Vercel / Windows 패키지:** 봇과 전투 판정이 브라우저의 Web Worker에서 실행됩니다. 게임 서버나 Node.js 설치 없이 플레이합니다.
- **LAN 멀티플레이:** `npm start`로 Node.js 서버를 열고 같은 네트워크에서 최대 8명이 플레이합니다. 서버에서 이동·충돌·사격·피격·점수를 판정합니다.
- **선택적 온라인 랭크·사용자 대전:** Java 21/Spring Boot·PostgreSQL과 인증된 공통 JS 전투 노드를 사용합니다. **일반: 개인전 랭크(4인)**, **랭크: 팀전 랭크(3:3, 배치 5판)**로 구성하며, 사용자 대전은 WAN 방 생성·목록·비밀번호·개인전/팀전을 지원합니다. 로컬 실행 방법은 [`online-server/README.md`](online-server/README.md)에 있습니다. 공개 온라인 서비스가 배포된 상태는 아닙니다.

튜토리얼·혼자 연습·LAN에는 계정, 유료 API, 외부 게임 서버가 필요하지 않습니다. 온라인 일반·랭크만 별도의 온라인 계정과 실행 중인 백엔드가 필요합니다. `~/engine`은 개발 시 이미지 제작에만 사용하며 플레이할 때는 필요하지 않습니다.

## 비개발자 친구에게 전달하기 (Windows 1인 플레이)

### 가장 간단한 방법: Vercel 링크

Vercel에 배포한 주소를 보내면 친구는 최신 **Edge 또는 Chrome**에서 주소를 열기만 하면 됩니다. Node.js/npm/Python을 설치할 필요가 없습니다. Vercel 배포 절차는 아래를 참고하세요.

### 파일로 보내기: Windows 포터블 ZIP

제작하는 컴퓨터에서 한 번 실행합니다.

```sh
npm install
npm run setup:packaging   # 최초 1회. 프로젝트 전용 Go 컴파일러 다운로드 + SHA-256 검증
npm run package:windows   # 1인 플레이 빌드 → Windows x64 EXE → ZIP
```

친구에게 **`release/LINKSHOT-Windows-x64.zip`만 전달**하면 됩니다.

1. ZIP을 **압축 해제**합니다.
2. 안에 있는 **`LINKSHOT.exe`를 더블클릭**합니다.
3. 기본 브라우저가 열리면 전장·무기·스킨을 고르고 **연습전 시작 → 교전 시작**을 누릅니다.
4. 게임 중에는 작은 실행 창을 열어 두고, 끝나면 그 창을 닫습니다.

실행 파일 안에 게임과 정적 웹서버가 포함되어 있습니다. **설치, 관리자 권한, 인터넷, Node.js, Python, Go가 친구 컴퓨터에 필요하지 않습니다.** 브라우저 및 WebGL 지원은 필요합니다. 서버는 `127.0.0.1`에만 열리며 LAN/인터넷으로 게임을 공개하지 않습니다. 기본 포트 `27007`이 사용 중이면 빈 포트를 자동 선택합니다. 브라우저가 자동으로 열리지 않으면 실행 창에 나온 URL을 직접 여세요.

전적/포인트/구매 외형은 **현재 Windows 사용자의 설정 폴더에 있는 `LINKSHOT/profile.json`**에 저장됩니다. 일반적인 Windows 환경에서는 `%APPDATA%\LINKSHOT\profile.json`입니다. 새 ZIP으로 교체하거나 브라우저 저장소를 지워도 이 파일은 유지됩니다. 실행 파일이 이미 켜져 있으면 가능한 경우 기존 로컬 실행 창을 재사용합니다. 저장 API는 로컬·동일 출처 요청만 허용하고, 파일은 임시 저장 후 교체합니다.

> Windows 10/11 x64 대상입니다. ARM64 패키지가 필요하면 `npm run package:windows -- --arm64`를 사용하세요. 빌드 컴퓨터에는 Go가 필요하며, 위 자동 설치는 macOS/Linux에서 시스템을 변경하지 않고 `.toolchain/`에만 설치합니다. Windows에서 빌드할 때는 [Go](https://go.dev/dl/)를 설치하세요. 실행 파일은 서명되지 않은 개인 테스트용이므로 SmartScreen/보안 소프트웨어의 확인 또는 차단이 있을 수 있습니다. 출처 및 `release/*.sha256`을 확인하고 보안 정책을 따르세요. 폭넓게 배포할 때는 코드 서명을 고려하거나 Vercel 링크를 사용하세요. Mac에서 교차 빌드한 파일의 실제 Windows 실행은 별도 확인이 필요합니다.

## 1인 플레이 빌드와 Vercel 배포

빌드하는 컴퓨터에만 Node.js 22 이상이 필요합니다.

```sh
npm install
npm run build        # 정적 1인 플레이 사이트 → dist/
npm run preview      # http://localhost:4173
```

`dist/`는 정적 웹사이트입니다. 플레이 중 Node.js를 실행할 필요가 없으며, Vercel/Nginx/Apache 등 정적 호스팅에서 실행합니다. Node 없이 로컬 확인을 하려면 Python이 있는 컴퓨터에서 `python3 -m http.server 8000 --directory dist`도 가능합니다. ES 모듈과 Web Worker 때문에 `dist/index.html` 더블클릭(`file://`)은 지원하지 않습니다. Windows 친구에게는 위 EXE 또는 Vercel 주소를 사용하세요.

**GitHub Actions는 Vercel 배포에 필요하지 않습니다.**

1. 이 프로젝트를 GitHub 저장소에 올립니다. `public/assets/`의 생성 이미지도 포함하고, `node_modules/`, `.toolchain/`, `artifacts/`, `release/`, `dist/`는 올리지 않습니다.
2. Vercel에서 **Add New → Project → 해당 GitHub 저장소 Import**를 선택합니다.
3. Framework는 **Other**, Build Command는 **`npm run build`**, Output Directory는 **`dist`**입니다. 포함된 `vercel.json`이 이 값을 설정합니다.
4. **Deploy**를 누르고 생성된 HTTPS 주소를 공유합니다. 이후 연결한 브랜치에 push하면 자동 배포됩니다.

이 배포에는 `/api`나 WebSocket 서버가 필요하지 않습니다. 1인 플레이는 `shared/simulation.js`를 브라우저 워커에서 실행합니다. LAN 버전의 메모리 기반 방 서버를 Vercel Functions에 그대로 올리는 구성이 아닙니다. Actions는 선택적으로 테스트 CI에만 사용할 수 있습니다. GitHub 업로드와 Vercel 배포는 별개이며, 사이트 공개는 Vercel에서 이 저장소를 Import한 뒤 진행합니다.

## LAN 멀티플레이 실행

Node.js 22 이상이 필요합니다.

```sh
npm install
npm start
```

- 이 컴퓨터: **http://localhost:3000**
- 친구: 터미널 또는 로비에 표시되는 **http://192.168.x.x:3000** 같은 LAN 주소
- 서버는 기본적으로 `0.0.0.0:3000`에서 수신합니다. 포트 변경: `PORT=8080 npm start`
- 개발 중 자동 재시작: `npm run dev` (재시작하면 진행 중인 방은 초기화됩니다.)

### 친구와 플레이

1. 서버 컴퓨터와 같은 Wi-Fi/유선 LAN에 접속합니다.
2. 한 명이 **LAN 대전 → LAN 방 만들기**를 누르고 설정 모달에서 방 이름·맵·규칙·AI·선택적 비밀번호를 정합니다.
3. **대기실 만들기** 후 대기실의 **초대 링크 복사**로 친구를 초대합니다. 또는 **방 목록 보기** 모달에서 5자리 코드나 목록으로 참가합니다.
4. 대기실에서 자신의 블루/레드팀과 출격 무기를 선택합니다. 방장은 대기 중인 참가자의 팀과 팀별 AI 인원·난이도를 구성하고, 다른 사람은 **준비 완료**를 누릅니다.
5. 방장이 **경기 시작**을 누르면 전장으로 진입합니다. 각자 **교전 시작**을 클릭해 마우스를 잠급니다. 진행 중인 방의 새 참가자는 대기실에서 팀·무기를 정한 뒤 **전장 입장**을 누르며 기존 교전은 계속됩니다.

방을 만들거나 목록에 참가하는 것만으로 경기 시계가 흐르거나 전장에 나타나지 않습니다. 대기자는 이동·사격·피격·자동 부활·완주 보상 대상에서 제외합니다. 방의 제한 시간은 실제 경기 시작부터 계산하며, 라운드 종료 후 같은 대기실에서 다시 팀을 구성합니다. 비밀번호는 목록이나 초대 링크에 포함하지 않으며 서버 메모리에 scrypt 해시로만 보관합니다.

> 접속되지 않으면 macOS의 로컬 네트워크 권한 및 방화벽에서 Node.js를 허용하세요. 게스트 Wi-Fi의 AP/client isolation은 기기 간 접속을 차단할 수 있습니다. 친구에게 `localhost`를 공유하면 안 됩니다. 인터넷 공개 서버를 전제로 만든 보안/인증 시스템은 없으므로 공유기 포트포워딩 없이 신뢰할 수 있는 LAN에서 사용하세요.

## 플레이 모드와 튜토리얼

로비에 **튜토리얼 / 혼자 연습 / LAN 대전 / 일반 / 랭크 / 사용자 대전** 여섯 진입 경로를 표시합니다.

### 작은 메인 화면, 모달 중심의 상호작용

로그인·회원가입·로그아웃은 모드 카드 안이 아니라 **우측 상단 프로필**에서 수행합니다. 기기 이름·전적·구매 정보는 같은 모달의 접힌 기기 프로필에 별도로 유지합니다. 모드 선택만으로 로그인 폼이나 방 설정이 메인 화면에 펼쳐지지 않습니다.

가입·로그인은 **아이디와 비밀번호만** 사용하며 가입 직후 표시 이름은 아이디입니다. 비밀번호를 입력하기 전에 **아이디 중복 확인**을 누를 수 있습니다. 중복 가입은 최종 DB 유니크 제약으로 다시 차단하고 **409 / 이미 존재하는 아이디입니다**를 반환하며, 기존 계정의 비밀번호를 덮어쓰거나 자동 로그인하지 않습니다. 로그인 후 같은 프로필의 **온라인 콜사인 → 콜사인 저장**에서 표시 이름을 1–24자로 변경할 수 있습니다. 로그인 아이디·기기 이름·전적은 그대로 유지하며 전장에는 다음 입장부터 반영합니다.

**방 만들기·방 목록/코드 입장·팀 대기실·매칭 대기**는 각각의 모달을 사용합니다. 연습·LAN·사용자 대전·랭크는 **같은 장비실**에서 총기 썸네일·3D 미리보기·성능·숙련도·소음기·스킨을 선택합니다. 로그인하면 모든 모드에서 **계정 LP·구매 무기·외형**을 공통 사용합니다. 랭크도 기본 4종과 계정에서 구매한 총기만 선택할 수 있습니다. 비로그인 기기 지갑·구매 내역은 지우거나 계정에 임의 합산하지 않고 별도로 보존합니다. 썸네일은 프레임마다 하나씩 준비합니다.

모달은 짧은 전술 패널 슬라이드/확대·페이드와 배경 흐림·헤더 라인 효과로 열고 닫습니다. 브라우저의 실제 dialog 포커스 격리·중첩 모달·Esc 처리를 유지하고, 닫힘 중 재열기와 3D 미리보기 자원 정리도 처리합니다. **동작 줄이기** 설정에서는 전환 애니메이션을 생략합니다. 팀 대기실은 실수로 Esc/배경 클릭만으로 방을 떠나지 않으며 **방 나가기**로 명시적으로 퇴장합니다.

메인은 화면 높이에 맞춰 전적·최근 10경기·모드·출격·장비·연결 메뉴를 배치하며 페이지와 기록 패널에 스크롤을 만들지 않습니다. 작은 화면은 배지·기록 카드를 압축하고 별도의 **전장 변경** 버튼을 사용합니다. 긴 설정 내용은 메인이 아닌 모달에서만 스크롤합니다.

출격 버튼을 카드 맨 아래로 억지로 밀어내지 않고 모드 설명 바로 아래에 둡니다. 출격 패널과 **랭크·무기·서버 연결** 카드는 하나의 오른쪽 레일로 묶으며, 넓은 화면은 위아래 정렬된 세로 카드, 작은 화면은 짧은 가로 카드를 사용합니다. 중복된 지도 카드는 제거하고 전장 선택은 **전장 변경**으로 유지합니다.

랭크 카드에는 로그인한 온라인 계정의 **티어·세부 단계·승급점수 또는 배치 경기/승수**를 표시합니다. 브론즈·실버·골드·플래티넘·다이아·챌린저에 각각 방패·날개·월계·블레이드·프리즘·왕관 형태의 독자적인 벡터 마크를 사용하며, 배치 중/미로그인에는 중립 마크를 표시합니다. 카드에서 랭크 상세 모달과 전체 티어 마크를 볼 수 있습니다. 마크는 외부 이미지나 추가 WebGL 렌더러 없이 가벼운 SVG로 표시하며, 기기 LP나 기기 승수로 온라인 티어를 추정하지 않습니다.

개인전은 **원형 궤도/헌터 문장**, 팀전은 기존 **방패 문장**으로 외형을 구분합니다. 플레이어 이름·대기실·점수판·킬 알림·사망 정보에는 두 모드 중 높은 공식 티어를 표시합니다(티어 → 단계 → RP 순 비교). LAN의 계정 마크는 선택적인 일회용 검증만 사용하며, Spring이 없어도 게스트 플레이는 계속 가능합니다. 클라이언트가 임의로 보낸 티어는 표시하지 않습니다.

모달의 헤더·닫기·하단 확인 버튼은 고정하고 필요한 경우 **내용 영역만** 스크롤합니다. 모달을 연 동안 배경 페이지는 스크롤하지 않으며, 닫으면 원래 버튼으로 포커스를 돌립니다. 연속 닫기와 닫힘 중 재열기도 현재 화면 위치에서 자연스럽게 이어집니다.

Java/Spring Boot 온라인 서비스의 로컬 개발·인증/DB·공통 JS 전투 노드 구성과 검증 방법은 [`online-server/README.md`](online-server/README.md)를 참고하세요. 온라인 API 주소를 넣지 않은 기본 정적 빌드에는 서버가 필요하지 않습니다.

macOS/Linux의 **LAN 대전은 터미널 두 개에서 `./online.sh`, `./fe.sh`만 실행**하고 **http://127.0.0.1:4173**에 접속하면 됩니다. Node 22 이상·`npm install`만 필요하며 Spring·Java·DB·로그인은 필요하지 않습니다. 계정·개인전/팀전 랭크·온라인 사용자 방을 이용할 때만 별도 터미널에서 **`./spring.sh`**를 추가합니다(Java 21·Maven 필요).

`spring.sh`는 계정·DB·매칭·정산 API(8080), `online.sh`는 LAN·인증된 온라인 전투를 분리하는 Node 노드(8090), `fe.sh`는 브라우저 화면과 동일 출처 LAN 프록시(4173)입니다. LAN은 FE의 `/lan/play` → 전투 노드의 `/lan/play`로 연결하며 온라인 `/play`의 계정 인증을 우회하지 않습니다. `LAN_ENGINE_URL`은 FE 서버에만 전달하고 브라우저 빌드에는 넣지 않습니다. 기존 `npm start`의 독립 LAN 서버도 그대로 유지합니다.

같은 LAN의 다른 PC에서는 FE를 실행한 PC의 `http://<사설-IP>:4173`에 접속합니다. **`./online.sh --lan` → `./fe.sh`**로 LAN 주소를 저장·출력할 수도 있으며 Spring은 없어도 됩니다. 계정 기반 온라인 모드도 다른 PC에 제공하려면 `./spring.sh`를 추가합니다. 기존 계정·DB·비밀키는 유지하며 인터넷 공개용 설정은 아닙니다.

- **튜토리얼·혼자 연습:** 정적 배포와 LAN 에디션 모두 브라우저 Web Worker로 실행합니다. LAN WebSocket이 끊겨도 이용할 수 있습니다.
- **LAN 대전:** `online.sh`+`fe.sh`의 로그인 없는 LAN 방, 또는 기존 `npm start` 서버를 사용합니다. 공개 정적 HTTPS 빌드는 LAN 프록시를 포함하지 않으며 기존처럼 로컬 서버 페이지로 이동합니다.
- **일반: 개인전 랭크 / 랭크: 팀전 랭크:** 각각 4인 개인전과 **3:3·팀 합산 40킬 선승**을 매칭하며 서버가 8개 전장 중 무작위로 선택합니다. 30초 뒤 표시된 AI로 빈자리를 보충하며 `RANKED_AI_ENABLED=false`이면 팀전 검색은 사람 6명을 기다립니다. 매칭 발견 후에는 **15초 안에 직접 수락**합니다. 미수락/거절 자리는 검색 AI 설정과 관계없이 AI로 대체하고 그 계정에는 전적·RP·LP를 부여하지 않습니다. 전원 미수락이면 경기를 취소합니다. 메인의 고정된 출격 버튼 자리에서 검색/수락 상태와 취소를 이용할 수 있습니다.
- **사용자 대전:** 온라인 계정으로 접속한 중앙 전투 서버에서 방 만들기·목록·코드/비밀번호 입장·방장 재경기를 이용합니다. 개인전/팀전·맵·목표 킬·시간·봇을 방장이 선택하고 진행 중인 방에도 참가할 수 있습니다. 방은 해당 전투 노드의 메모리에 유지하며 마지막 사람이 나가거나 노드가 재시작되면 종료됩니다. **사용자 대전 결과는 경쟁 점수·온라인 전적·LP·영구 숙련도에 반영하지 않습니다.**

랭크는 첫 그래픽 준비 완료를 기준으로 **공통 서버 시작 시각**을 정합니다. 늦게 로딩한 사람은 3초부터 볼 수도 있고 재접속해도 시간을 초기화하지 않습니다. 시각이 지났는데 아직 준비 중인 참가자가 있으면 기다렸다가 모두 준비된 순간 추가 카운트 없이 시작합니다(30초 준비 제한 초과는 안전 취소). 준비 중에는 **F 전체화면·E 공통 장비실**을 사용할 수 있고 이동·사격·피해는 차단합니다. 시작할 때 포커스 이탈을 ESC 메뉴로 처리하지 않으며 작은 클릭 안내로 조작을 활성화합니다. 승패 이펙트 **5초** 후 서버 영수증의 MMR·RP 증감과 배치 진행을 표시합니다. 배치 완료·승급·강등 시 **이전 랭크 마크가 먼저 보이고 새 마크로 전환**됩니다. 동작 줄이기 설정은 즉시 최종값을 표시합니다.

개인전·팀전 실력 점수는 각각 1000에서 시작하며 상점 LP와 분리합니다. 개인전은 최종 개인 순위, 팀전은 팀 합산 승패로 점수가 오르내립니다. 각 모드에서 **배치 포함 첫 20판은 MMR·RP 상승과 하락이 모두 2배**, 21판부터 기본 배율입니다. 배치 5판의 RP는 최초 티어에 반영하며, **5전 전승·20킬 이상·누적 K/D 1.5 이상이면 골드 V**로 시작할 수 있습니다. 기존 티어·과거 영수증·LP는 변경하지 않습니다. 배치 후 100 RP마다 승급하며 챌린저 정원은 모드별 상위 200명입니다.

로그인 상태의 메인·장비실·외형 상점은 모드를 바꿔도 **동일한 계정 LP와 구매 내역**을 표시합니다. 구매 가격·잔액·중복 구매는 Spring/PostgreSQL이 검증하며 브라우저의 가격/보유 목록을 계정에 가져오지 않습니다. 로그인과 회원가입은 별도 화면이며 아이디 중복 확인·비밀번호 확인은 회원가입에만 있습니다. 계정 LP는 랭크 종료 정산 때 지급합니다. 비로그인 LAN/연습의 기기 보상은 기존 로컬 장부에 보존하고, 비경쟁 사용자 대전·튜토리얼·목표 모드는 LP를 지급하지 않습니다.

메인에는 **개인전·팀전 각각의 티어·배치/승급 진행도**, 선택한 모드의 **승/무/패·승률·K/DA·킬/데스/어시스트·최근 10경기**를 표시합니다. 티어·MMR·RP·전적은 모드 사이에 섞이지 않습니다. 최근 경기는 10개 고정 슬롯으로 배치하고 메인과 기록 패널 모두 스크롤을 사용하지 않습니다. V11은 팀전 티어를 보존하며 기존 개인전 MMR·완료 기록으로 개인전 배치를 이어갑니다. 과거에 수집하지 않은 어시스트는 0이고, 이후 경기는 실제 서버 판정으로 집계합니다.

최근 전적은 맵 썸네일·승패 배지·K/D/A·RP가 정렬된 전투 기록 패널입니다. 하단 전장 영역은 여섯 모드에 동일하게 예약하며 개인전/팀전 랭크에서는 자동 배정, 튜토리얼에서는 훈련장을 표시합니다. 모드를 바꿔도 전장 영역의 높이와 위치는 바뀌지 않습니다.

대시보드 렌더링(`public/competitive-dashboard.js`)·통계 계산(`public/competitive-stats.js`)·서버 전적 조회(`CompetitiveRecords.java`)를 계정/매칭 로직에서 분리했습니다. 사용하지 않는 팀 전장 콘셉트 4장은 `docs/maps/concepts/`로 이동하고 출처를 보존했으며, 배포 파일 약 8.5 MiB를 줄였습니다. 실제 사용하는 모델·소리·텍스처·라이선스는 유지합니다.

랭크 서버는 입장·준비·사망 후 장비 선택에서 모두 **기본 총기와 실제 계정 구매 무기**만 허용합니다. 준비 중 구매한 총기는 중앙 계정 장부를 다시 확인한 뒤 적용하며 브라우저의 보유 플래그는 무시합니다. 소음기는 해당 무기의 온라인 Lv.5가 필요합니다. 접속 종료 후 **30초 안에는 동일한 플레이어 상태로 재접속**하며, 그동안 전투는 멈추지 않습니다. 유예가 지나면 탈주 처리하고 LP를 지급하지 않으며 최하위로 정산합니다. 새 계정은 **0 LP·기본 4종**으로 시작합니다.

튜토리얼은 멀티플레이 맵 풀과 분리된 작은 훈련장에서 **실제 입력·충돌·사격·장비·리스폰 규칙**으로 진행합니다. 시점/WASD/Shift 무음 걷기 → 점프/앉기/계단 → 표적/정조준/재장전 → G로 바닥 총 교체 → 초급 AI 교전 → 3초 리스폰 시범 → 마무리 표적 연습의 일곱 단계입니다. 리스폰 시범은 교관이 나타난 뒤 **Enter로 직접 시작**하고, 복귀 후 총과 체력을 볼 수 있도록 최소 2초를 유지한 다음 **Enter로 확인해야 마지막 연습으로 이동**합니다. 마지막 AI는 이동하거나 공격하지 않으며, 처치하면 3초 뒤 같은 위치·방향에서 다시 나타납니다. 한 번 처치·재등장을 확인한 뒤에도 계속 연습할 수 있고, **원할 때 Enter를 눌러야 완료**합니다. 일반 경기의 킬/시간 제한으로 자동 종료되지 않습니다. 사망해도 현재 학습 단계는 유지하며 Esc 메뉴에서 단계 확인/완료, 다시 시작, 건너뛰기를 선택할 수 있습니다.

튜토리얼은 **킬/데스·무기 숙련도·LP·라운드 보상과 경쟁 점수에 반영하지 않습니다.** 완료 여부만 브라우저에 표시용으로 저장합니다. 온라인 모드의 기록도 기존 로컬 장부와 명시적으로 분리합니다.

### 팀 데스매치 (LAN·사용자 대전)

방 만들기에서 **팀 데스매치**를 선택하면 초기에는 블루/레드팀을 균형에 맞춰 배정하되, **대기실의 팀 목록 머리글 `이 팀으로 이동`이나 내 행의 팀 선택으로 직접 이동**할 수 있습니다. 팀을 바꾸면 준비가 해제됩니다. 방장은 대기 중인 다른 참가자와 AI도 배치할 수 있습니다. 최대 8개 슬롯 내에서 비대칭 AI 팀도 허용하며, 시작하려면 양 팀에 사람 또는 AI가 있어야 합니다.

LAN·사용자 방 생성 화면의 공통 난이도와 대기실의 `추가 AI 난이도`는 제거했습니다. **방장은 대기실의 각 AI 행에서 초급/중급/고급/최고급/극한을 따로 변경**하며, 이미 가득 찬 방에서도 기존 AI의 설정만 바꿀 수 있습니다. 다른 AI의 설정·인원은 유지됩니다. 혼자 연습은 대기실 없이 시작하므로 연습 교전 설정의 단일 난이도를 그대로 사용합니다. 진행 중인 AI 구성은 변경할 수 없습니다.

매칭 AI는 경기 생성 시 고정한 해당 모드 평균 MMR에서 **1,100/1,500/1,900/2,300**을 기준으로 난이도를 고릅니다. 기본 추첨은 **아래/기준/위 단계 15%/70%/15%**이며, 팀전에서 수락한 사람이 더 적은 팀은 AI 최대 두 자리를 기준보다 한 단계 높입니다(최대 극한). 개인전의 **+200은 AI 난이도에만** 사용하며 사람 매칭·실제 MMR·정산은 그대로입니다. 체력·무기 피해량은 동일합니다. 정적 벽 공간 인덱스·시야 조기 종료·할당 없는 교차식·A* 경로 검색으로 반복 계산을 줄였으며, 이동·시야·사격의 60Hz 갱신은 유지합니다. 상세 규칙과 성능 측정 한계는 [`docs/ai-difficulty.md`](docs/ai-difficulty.md)를 참고하세요.

난이도가 높을수록 탐지 거리·시야각·명중 정확도가 좋아집니다. 기본 탐지는 **75/90/105/120/135m**, 저격소총은 추가 **40m**이며 벽·실제 무기 사거리는 우회하지 않습니다. 저격 조준은 고정 시간이 아니라 **난이도·거리별 범위에서 한 번 무작위 추첨**하며, 100m 기준 초급 1.16–1.96초부터 극한 0.50–0.89초까지 차등 적용합니다. 시야 단절·이동 시 다시 조준·추첨하고, 먼 적일수록 더 오래 조준합니다.

교전 도중에는 **Esc → `팀 변경 / 대기실` → 원하는 팀 클릭 → `전장 입장`**을 이용합니다. 현재 생명을 포기해 사망 1회와 사용 중인 총 드롭을 처리하고 새 팀에서 다시 부활합니다. 다른 참가자의 생명·탄약·경기 시간·라운드는 초기화하지 않습니다. 교전 중인 몸의 팀만 즉시 바꾸는 패킷은 서버가 계속 거절합니다.

**참가자에게 보이는 첫 팀은 임시 배정**입니다. LAN·사용자 방의 목록·코드·비밀번호·초대 링크로 참가하면 대기실 상단의 큰 **BLUE / RED** 버튼을 직접 눌러 확정한 후 준비하거나 진행 중인 전장에 입장합니다. 선택 전에는 준비·입장이 잠기고, 버튼에도 **`레드팀 · 전장 입장`**처럼 실제 입장 팀을 표시합니다. 방장이 내 팀을 바꾸면 다시 확정해야 합니다. 방장은 생성 시 선택한 팀(또는 자동 배정)으로 시작합니다.

팀전에서는 사람·AI·사망한 몸·1인칭 소매의 **복장 색을 기본적으로 블루/레드로 통일**합니다. 얼굴·피부·무기 색상·장비 형상·피격 범위는 바꾸지 않고, 저장된 캐릭터 외형·스킨·구매 내역도 덮어쓰지 않습니다. 개인전에서는 원래 복장 색을 사용합니다.

기존 8개 맵은 긴 축 반대쪽, 신규 팀 전장은 지정된 팀 진입부로 스폰을 나눕니다. 처음 입장·사망 후 부활·재경기에도 자기 팀 구역을 유지합니다. 아군은 피해를 받지 않으며 아군 몸에 맞은 탄/칼은 뒤의 적을 관통하지 않습니다. 봇도 같은 팀은 공격하지 않습니다.

### 이동 거점전·협동 방어전

연습의 **교전 설정**, LAN·사용자 방의 **교전 방식**에서 개인전/팀 데스매치/이동 거점전/협동 방어전 중 선택합니다. 호환되지 않는 전장은 UI와 서버 양쪽에서 차단합니다. 일반·랭크 매칭 대상은 기존 8개 전장입니다.

파운드리·롱레일·드라이독·블록 나인·화이트아웃·레드라인은 여러 곳에서 외곽을 안으로 접어 작업동·건물·절벽 턱이 플레이 공간을 좁히도록 구성했습니다. **롱레일은 중앙 정비 골목 하나**, **블록 나인은 중앙 상가 양쪽의 골목 두 개**로 남북 구역을 연결합니다. 레드라인은 북쪽 긴 사선을 유지하고 남쪽 정비로를 굽혔습니다. 외곽과 골목은 실제 이동·사격·AI 경로에 반영되며 전술 브리핑에 표시됩니다. 기존 온실·야시장과 전용 전장의 규칙은 바꾸지 않았습니다.

**드라이독**은 중앙 창고와 북서쪽 하역동의 지하 1층을 연결했으며 지상 우회도 가능합니다. **화이트아웃**은 동·서 연구 구역 사이가 지상 눈벽으로 막혀 있습니다. 두 구역을 잇는 길은 B1의 넓은 연구 통로와, 따뜻한 조명과 엄폐물이 있는 좁고 굽은 정비 우회로입니다. 동쪽 연구동과 정비동 사이의 옥상 다리는 그대로이며, 두 건물을 넓히고 창을 각각 두 개로 줄였습니다. 연구동의 계단은 반대편에 있고 실내 칸막이가 긴 사선을 끊습니다. 지하 입구는 `B1`으로 표시되며, 미니맵에서는 정비 우회로를 주황색으로 구분합니다.

- **이동 거점전 / RELAY:** 한 번에 한 거점을 점령하며 45초마다 A→B→C로 이동합니다. 한 팀만 진입해 있으면 초당 1점, 양 팀이 있으면 득점 정지입니다. 킬은 거점 점수에 더하지 않습니다. 기본 150점 선취/5분 종료이며 목표 점수는 30–200점으로 설정합니다. AI도 거점 진입·고지대 이동·수비를 수행합니다.
- RELAY의 접근로와 각 거점에는 서서 숨는 차폐벽과 앉아서 쓰는 낮은 엄폐가 있습니다. **점령 득점 게이지**는 다음 +1점까지의 진행을 표시하고, 양 팀 목표 점수·거점 남은 시간도 막대로 표시합니다. 전장 안의 표지와 바닥 영역은 블루/레드 점령·경합·중립 상태를 구분합니다. 점령 준비 시간을 새로 추가한 것이 아니라 기존 초당 득점을 시각화한 것입니다.
- **협동 방어전 / BASTION:** 수비팀은 최대 4명(지원 AI 포함)입니다. 적은 **공세 번호 × 4명**이 동시에 출격하며 총원·동시 적 수에 고정 상한을 두지 않습니다. 공세 설정의 10회 제한도 제거했습니다. 최초 준비 10초, 공세 사이 7초이며 시작·격퇴 이펙트가 표시됩니다. 적 체력 100, 코어 내구도 1000과 실제 벽·총알 판정은 유지합니다. 높은 공세는 하드웨어에 비례해 부하가 증가합니다.
- BASTION은 **96 × 88m**로 확장했습니다. 북쪽 방벽·펌프 야드·중앙 지원 데크·양쪽 1.8m 고지대·후방 코어실로 방어선을 나눕니다. 12개 공세 스폰은 고정 순환이 아니라 점유·시야·거리·최근 사용을 고려해 무작위 선택합니다. 수비팀도 8개 후방 위치에서 안전하게 무작위 부활합니다. 코어 앞·양옆의 높은 차폐벽과 덮개가 초기 사선을 막으므로 적은 측면을 돌아 후방 입구로 침투해야 합니다. 코어 자체의 체력이나 피해 규칙을 바꿔서 보호하지 않습니다.
- 두 신규 규칙은 경쟁 레이팅·기기 전적·영구 숙련도·LP에 반영하지 않습니다. 기존 프로필과 개인전/팀 데스매치 보상은 유지합니다. 연습에서는 같은 규칙을 브라우저 워커에서 서버 없이 실행합니다.

**팀원 전체의 누적 킬 합계가 방의 목표 킬에 먼저 도달한 팀이 승리**합니다. 제한 시간이 먼저 끝나면 합계가 높은 팀, 같으면 무승부입니다. 중도 이탈해도 이미 얻은 팀 점수는 유지합니다. HUD·이름표·점수판·미니맵에 팀과 점수를 표시합니다. LAN의 승리 보상은 승리한 팀원 모두에게 적용하고, 비경쟁 사용자 대전에는 LP를 지급하지 않습니다.

## 구현된 내용

- 12개 독립 레이아웃, 충돌·점프·엄폐물·그림자, 실제 경사면·원형 발판/구멍, 높이 레이어를 따르는 AI 경로와 미니맵
- 전장마다 실제로 올라설 수 있는 **계단식 발판 3–4개와 추가 엄폐물 12개**를 배치했습니다. 야시장은 좁은 비대칭 동선에 맞춰 발판 3개, 나머지 전장은 4개입니다. 낮은 계단은 걸어서 오르내리고, 1.8m 발판은 계단이 없는 면에서도 점프로 올라갈 수 있습니다. 가장자리 지지/착지는 측면 충돌과 같은 범위를 사용하며, 발판 밖으로 벗어나면 중력이 적용됩니다. 높은 위치는 실제 사격 시야에도 반영됩니다.
- `C` 또는 `Ctrl`을 누르는 동안 앉기: 낮아지는 시점·머리/몸통 피격 범위, 느린 이동과 조용한 발소리, 낮은 엄폐 뒤 숨기. 머리 위 공간이 부족하면 자동으로 앉은 자세를 유지합니다.
- 최대 8명 개인전, 5자리 방 코드, 여러 방, 초대 링크, 방장 자동 위임
- 최대 8명 LAN 대전, 0–7개 연습 봇(사람이 참가하면 봇이 비워짐), 초급/중급/고급 선택. 정적 배포는 1인+최대 7봇입니다.
- 봇끼리도 싸우는 개인전 AI: 인간 우선 타기팅 없음, 0.6–1.0초 반응 지연, 약 63°/초의 느린 몸 회전, 지연된 위치 추적과 조준 오차
- 초급 봇의 기본 자동소총 사격은 명중률이 낮은 짧은 2–3발 연사를 사용하며, 탄 사이 최소 0.45초와 연사 후 0.65–1.0초 휴식이 있습니다. 고유 3점사 무기의 점사 내부 주기는 무기 설정을 따릅니다. 봇 난이도가 플레이어의 무기 피해량이나 마우스 감도를 바꾸지는 않습니다.
- AI마다 동률 경로의 우회 방향을 다르게 선택하고 잠시 경로를 유지하며, 좌우 이동 주기와 무리 간 간격도 변화를 줍니다. 계단·몸체 충돌·엄폐 검증은 유지합니다. 실제 적 총성/근접 탄도에는 지연 후 더 빠르게 시선을 돌리지만 마지막 소리의 방향만 기억하며 벽 너머 현재 위치를 추적하지 않습니다. 소음기·차폐·거리 감쇠를 적용하고, 소총/지정사수/저격총은 간헐적인 원거리 관찰 구간에서 무기 사거리 안의 표적만 교전합니다.
- 위 봇 설정은 **초급(기존 반응/조준 설정)**입니다. 중급은 반응 350–550ms·최소 탄 간격 300ms, 고급은 반응 180–300ms·최소 탄 간격 180ms이며 무기 자체의 발사 주기보다 빨라지지 않습니다. 봇은 소총·SMG·산탄총·저격총·권총·LMG·DMR을 나눠 들고 플레이어와 동일한 무기별 피해/거리 감소/헤드샷을 적용합니다. 기존 15 고정 피해 보정은 제거했습니다. 체력은 모두 100입니다.
- 소총 AI는 교전 거리 안에서도 좌우로 움직이며 사격합니다. 저격 AI는 쿨다운 사이에 재배치하고, 지상에서 약 220ms 조준을 안정시킨 뒤 멈춰 확대 사격합니다. 중장거리 저격·엄폐 재장전에는 앉기도 사용합니다. 조준 회전 제한과 초급의 반응 지연은 그대로 유지합니다.
- 경로는 0.5m 격자와 플레이어 몸 너비를 포함한 이동선으로 검사합니다. 열린 구간은 앞쪽 경로점을 이어 부드럽게 이동하고, 벽 모서리에서는 회피·진행 정체 시 재탐색합니다. 계단의 지속 경로는 별도로 보존합니다. 낮은 통로에서는 앉고, 짧은 낮은 엄폐물(최대 1.25m) 앞에서는 머리 공간·착지면을 확인한 뒤 일반 점프를 사용합니다. AI도 사람과 같은 점프·앉기·충돌 규칙을 사용하며 벽 관통이나 공중 방향 전환은 없습니다.
- 8개 전장에 **6–9m 높이의 진입 가능한 건물 34개와 추가 엄폐벽 64개**가 있습니다. 건물마다 층별 창의 위치·폭과 계단 방향이 다르고, 여러 문과 독립 계단을 둔 건물도 있습니다. 드라이독의 17×14m 창고는 세 면에서 진입할 수 있으며 폭 3m의 직선 계단과 작업용 계단이 따로 있습니다. 블록 나인·화이트아웃·야시장에는 옥상 연결교가 있고, 야시장 다리는 지붕을 덮었습니다. 전술 지도에 문·계단·옥상 다리를 표시하며, 보이는 구조를 그대로 이동·사격·AI 경로에 사용합니다.
- 돌격소총·기관단총·산탄총·저격소총·권총·경기관총·지정사수소총, 무기별 탄창/연사/재장전/반동/효과음, 헤드샷과 거리별 피해량
- 무기별 걷기/달리기 속도와 정조준 이동 페널티: 권총/기관단총은 가볍고 경기관총/저격총은 무겁습니다. 라이플 정조준은 실제 사격과 같은 시점/각도를 사용하며, 화면 반동 때문에 조준점과 탄착점이 어긋나지 않습니다.
- 산탄총 8개 산탄의 개별 피격 판정, 저격 스코프, 무기별 독립 탄창, 재장전 취소 및 교체 지연
- 무기와 캐릭터 공통 스킨 6종, 실제 3D 장비 미리보기, 시작 장비/전장/스킨 브라우저 저장
- 서버 권위 이동 및 피격 판정, 사격 속도 제한, 오래된 입력 자동 해제
- 3초 리스폰, 1.5초 스폰 보호 (사격하면 해제)
- 맵당 34–66개 스폰: 지상 24곳과 2·3층·옥상. 스폰 전용 ㄷ자 벽 대신 건물·화물·설비로 시야를 가리고 적에게 보이지 않는 지점을 우선 선택합니다.
- 사망 후 입력·총성·섬광·예측 점사를 클라이언트와 서버에서 차단합니다. 3초 대기에 처치한 상대·무기·해당 무기의 숙련도 레벨을 표시합니다.
- 타이머 아래 킬·더블킬·트리플킬 등 연속 처치 효과와 무기 레벨·진행 게이지. 연속 처치는 5초 이내 다음 킬로 이어지며 사망하면 초기화됩니다.

- 미니맵 (시야 내 상대만 표시), 실제 녹음 총성과 로컬 효과음, 감도·FOV·음량·그래픽 설정
- **설정 → 총기 표시 위치 → 오른손/왼손**을 선택할 수 있습니다. 1인칭 총기·손·재장전·총구 섬광만 좌우 반전하며 설정은 브라우저에 저장됩니다. 조준점·탄도·피격 판정·다른 플레이어에게 보이는 모델은 바뀌지 않습니다.

- 무기명·남은 탄약은 **우측 하단에만** 표시합니다. 하단 중앙의 중복 무기/탄약 표시는 없습니다.
- 중앙 방향 문구는 표시하지 않습니다. 피격에는 짧은 혈흔 입자/표면 흔적이 나타납니다. 사망 시에는 마지막 자세에서 양손을 놓고 무릎이 꺾이며 뒤로 넘어집니다. 바로 뒤가 벽이면 가능한 방향으로 몸을 돌리거나 그 자리에서 주저앉습니다. 사망 모션과 최대 10초간 남는 시체는 시각 효과이며 이동·명중·드롭 판정을 바꾸지 않습니다. 시체는 최대 8개입니다.
- LAN WebSocket 연결 복구 (진행 중인 방 자동 재참가는 하지 않음), 온라인 30초 재접속 유예
- 기기별 자동 ID, 누적 킬/데스/KD·킬 비율·완료 경기·승리·포인트 자동 저장과 메인 화면 표시
- 라운드 종료 때 한 번만 지급하는 보상, 포인트로 구매/장착하는 능력치 없는 캐릭터 외형 상점

키보드·마우스와 WebGL을 지원하는 데스크톱 브라우저가 필요합니다. 모바일 플레이와 터치 조작은 현재 지원하지 않습니다.

산탄총/저격총/반자동 권총/지정사수소총은 클릭할 때마다 한 발씩 발사하며 Glock 18C는 자동권총입니다. **생존 중 숫자키·휠·임의 네트워크 입력으로 무기를 바꿀 수 없습니다.** 사망 후 E로 보유 무기를 선택하면 다음 부활부터 적용하고, 선택 대기는 사망 후 최대 15초입니다. 선택 후 마우스 잠금을 복원하며 브라우저가 거절하면 재개 버튼을 표시합니다. 앉기·일어서기는 약 100ms 동안 눈높이·피격 범위·이동속도와 몸체 모션이 함께 전환됩니다. 지상에서는 이동·Shift 걷기와 앉기를 함께 사용할 수 있고, 공중에서는 새로 앉을 수 없습니다. 낮은 천장 아래의 강제 앉기는 안전하게 유지합니다.

지상에서 완전히 앉으면 **실제 탄퍼짐과 조준선이 30% 감소**합니다. 100ms 자세 전환량을 함께 사용하며 이동·연사·정조준에도 적용하지만 공중에는 보너스가 없습니다. 클라이언트가 보낸 임의 자세 수치가 아니라 서버의 실제 앉기 상태로 판정합니다.

G는 **바닥에 내려앉은 총과의 교체만** 허용합니다. 1.8m 이내·높이 차 1.25m 이내의 총 중 벽/바닥을 뚫지 않고 닿는 가장 가까운 총을 서버가 고릅니다. 이전 총을 바닥에 남기며 **남은 탄약과 총기 색상을 그대로 교환**합니다. 성공한 교체는 재장전/점사/누르던 방아쇠를 취소하고 350ms 준비 시간을 적용합니다. 교체 대상이 없으면 현재 장비·탄약·재장전을 유지하며 나이프로 전환하지 않습니다. 사망/교체로 생긴 드롭은 해당 층 바닥에 내려앉고 60초 뒤 사라지며 방당 최대 32개, 재경기에는 모두 정리합니다.

주운 미해금 총도 해당 생명 동안 사용할 수 있지만 **영구 소유권·상점 포인트·저장된 다음 부활 장비는 바뀌지 않습니다.** 주운 소음기는 그 총에 붙은 채 임시로 사용하며 해금 권한을 주지 않습니다. 기존 나이프 장비/처치 기록은 호환성을 위해 유지하지만 G로 나이프를 지급하는 경로는 없습니다. LAN 서버와 브라우저 워커가 같은 장비 규칙을 사용하고, 이전 생명·장비·라운드의 지연 요청과 중복 G 요청은 거부합니다. 변경된 맵과 조준 규칙을 서버·클라이언트가 함께 쓰도록 전투 프로토콜을 **29**로 올렸습니다. 진행 중인 방을 마친 뒤 전투 서버와 프런트엔드를 같은 버전으로 갱신하고 브라우저를 새로고침하세요.

### 위치·시야 안정성

클라이언트 이동과 LAN·온라인·솔로의 권위 시뮬레이션 타이머는 프레임이 33ms를 넘더라도 최대 250ms의 경과 시간을 같은 작은 물리 단계로 따라잡습니다. 기존처럼 낮은 FPS에서 이동 시간이 버려져 서버에 끌려가는 현상을 줄이며, 장시간 멈춘 뒤에는 무제한으로 이동을 재생하지 않습니다. 서버의 큰 오차 보정·충돌·실제 부활 규칙은 그대로 유지합니다.

스냅샷에는 방 전체에서 계속 증가하는 순번이 있어 중복·과거 상태가 현재 생명이나 라운드를 되돌리지 못합니다. 재시작 이벤트를 다시 받았다는 이유만으로 위치·조준을 초기화하지 않으며 실제 라운드/생명 변경만 초기화합니다. 포인터 잠금·창 크기 전환 직후의 큰 커서 워프는 걸러내되, 평상시 빠른 180도 조준은 제한하지 않습니다. 이는 재현한 코드 경로의 수정이며 모든 네트워크 지연이나 장시간 프레임 정지에서 서버 보정이 없어지는 것은 아닙니다.

방 생성 시 목표 **1–200킬 / 제한 시간 1–60분**을 선택할 수 있으며 기본은 20킬/5분입니다. 해당 방 참가자 모두에게 적용하고 재경기에도 유지합니다. 저격총은 정조준 발사 직후 줌을 풀며, 클릭 순간의 조준각/ADS를 서버가 보존하므로 반동·줌 해제 입력이 같은 틱의 탄착점을 바꾸지 않습니다. 빠른 단발 입력과 최대 200ms 이내의 표시 지연을 보정하고, 어깨·발 쪽 몸통 판정의 빈틈도 보강했습니다. 스폰 보호는 유지하되 청색 링/명중 표시로 구분합니다.

Shift나 정조준 없이 지상에서 움직여도 추가 탄 퍼짐은 작습니다. **Shift 걷기와 우클릭 정조준의 탄 퍼짐은 같고**, 기본 달리기보다 정확합니다. 정지하면 더 좁아지지만 줌을 해도 미세한 무작위 퍼짐은 남습니다. AK-47과 MR–14는 위력 대신 넓은 퍼짐, M4A1·AN-94와 M14는 더 촘촘한 조준이 특징입니다. 연사 중 추가 퍼짐도 소총마다 다릅니다. 조준선 바깥 표시와 정조준 링이 실제 퍼짐을 반영하며, 점프·반동·확대 중에도 중심점은 화면 중앙에 고정됩니다.

**SR–1 / AWP / Barrett M82**는 집중하지 않은 노줌 사격의 퍼짐이 크고, Shift나 정조준 중에도 이동하면 불리합니다. 정지 정조준은 SR–1이 가장 촘촘하고 AWP와 M82 순으로 넓어집니다. 공중 사격은 더 크게 퍼집니다. 서버/LAN·1인 워커·조준선은 같은 계산을 사용합니다.

몸통은 **최대 1.2배**, 팔은 어깨에서 손끝으로 갈수록 연속적으로 **1.2 → 0.5배**의 피해 배율을 적용합니다. 머리는 기존 무기별 헤드샷 피해/거리 감소를 유지하고, 다리의 기본 배율은 1배입니다. 팔·손의 캡슐 근사 판정과 몸통 중 먼저 맞은 부위를 사용하며, 팔이 몸통 앞을 가리면 팔 피해가 적용됩니다. 산탄도 탄알마다 부위·거리 배율을 계산한 뒤 합산합니다. 남녀/외형에 따른 차이는 없으며 지연 보정에는 당시 시선·무기·앉기 자세도 포함됩니다.

유효한 피해를 받으면 **1초 동안 이동속도가 30% 감소**합니다. 연속 피격은 종료 시간만 갱신하고 배율은 중첩하지 않습니다. 조준 감도·시점 회전·중력은 그대로이며 공중의 저장된 이동 방향도 유지합니다. 스폰 보호로 막힌 탄은 둔화를 주지 않고 사망/부활 시 효과를 초기화합니다. 히트마커는 중앙이 빈 대각선 4개에 **굵은 선·어두운 외곽선**을 겹쳐 밝고 어두운 배경 모두에서 보이도록 했습니다. 일반 명중은 흰색 38px/240ms, 헤드샷은 금색 42px/320ms, 스폰 보호 명중은 청색 방패 38px/220ms로 구분하며 표시 시간의 72%까지 완전한 밝기를 유지한 뒤 사라집니다.

발사로 생긴 일시적인 시점 반동은 마지막 발사 후 약 150ms부터 마우스로 조준한 방향으로 부드럽게 복귀합니다. 복귀 중 마우스를 움직이면 그 조준을 새 기준으로 유지하며, 단발·연사·프레임 지연 후에도 잔여 반동이 영구 누적되지 않습니다. 복귀 중에도 화면과 서버에 보내는 조준각은 동일합니다.

23종의 주요 총몸은 직육면체를 덧붙이는 대신 **연속 윤곽·둥근 모서리·면취·테이퍼**로 제작합니다. 구멍이 열린 총구/조준기, 곡선 탄창, 엄지 구멍 개머리판과 가스관·피딩 벨트·원통형 펌프를 무기별로 구분하며, 금속·폴리머·고무·목재의 거칠기와 미세 표면도 다르게 표현합니다. AK/M14의 목제 외장, MP5의 원통형 리시버, P90의 낮은 상부 탄창, 저격총의 열린 광학 튜브 등은 1인칭·다른 플레이어·장비실에 같은 모델로 적용합니다. S686은 장전할 때 총열·받침 손·장착한 두 소음기가 함께 꺾입니다.

**FAMAS는 높은 홀로사이트를 캐리 핸들 위에 다시 쌓지 않습니다.** 낮은 일체형 캐리 핸들과 통합 가늠자를 사용해 비조준에서 수평선 위를 가리지 않으며, 낮춘 조준점에 맞춰 실제 ADS도 중앙에 정렬합니다. 표시용 형상만 바꾸고 피해량·탄 퍼짐·발사 속도·반동·총성·총구 기준점과 기존 손 자세는 유지합니다. 정적 부품은 재질별로 합치고 경기 단위로 메시 버퍼를 공유해 세부 형상 때문에 그리기 호출이 불필요하게 늘지 않도록 합니다.

AK/FAMAS의 전방 가늠쇠 날과 지지대를 더 얇고 낮게 만들고, 소총·LMG·DMR의 광학 조준기 테두리와 받침대 중앙을 비워 아래쪽 시야를 확보했습니다. **총열 길이·실제 조준축·총구·전투 수치는 변경하지 않았습니다.**

MP5와 철제 조준기 계열에 남아 있던 **가까운 후방의 높은 사각 받침**도 개방형 두 다리/얇은 가늠자로 바꿨습니다. 전방은 낮은 개방형 지지대 위에 짧고 얇은 중심 기둥을 연결하고 후드도 얇게 만들어 ADS 아래쪽이 긴 검은 벽처럼 보이지 않게 했습니다. 조준 날 끝과 기존 조준축은 그대로 유지하며 부품이 떠 있지 않은지도 검사합니다.

1인칭 비조준 총기는 기존보다 **우측 하단**에 두어 중앙 시야를 덜 가립니다. 왼손 설정에서는 동일하게 좌측 하단으로 반전합니다. 정조준은 총을 기울여 보정하지 않고 **가늠쇠 끝·뒤쪽 가늠자 틈·앞쪽 보호 링의 실제 중심**을 같은 축에 맞췄습니다. AK-47·FAMAS·MP5·산탄총과 권총의 정렬 및 SPAS-12 접이식 개머리판의 시야 간섭을 수정했으며, 광학 조준경의 기존 중심·줌 배율·탄도·피격 판정은 유지합니다. 23종의 실제 조준기 형상을 양손·FOV 65/82/105에서 투영해 검사하고, 비조준 총기가 가리는 중앙 영역도 렌더 픽셀로 비교합니다.

**공중에서는 이동 방향과 속도를 바꿀 수 없습니다.** 점프하거나 발판에서 떨어지는 순간의 월드 좌표 수평 속도를 착지까지 유지합니다. WASD를 놓거나 반대로 누르고, 시점을 돌리거나 Shift/정조준을 바꿔도 공중에서 가속·감속·방향 전환이 되지 않습니다. 정지 점프는 공중에서 이동을 시작할 수 없습니다. 마우스 조준과 중력·벽/천장/착지 충돌은 정상 작동하며 착지하면 지상 이동 조작을 다시 받습니다. 좁은 발판은 공중 제동 대신 이륙 전에 속도와 방향을 맞추세요. 서버/LAN·1인 워커·클라이언트 예측이 같은 규칙을 사용합니다.

3인칭 총열과 총구 섬광은 가까운 실제 벽에 겹친 부분을 잘라 건물 외벽 밖으로 드러나는 현상을 방지합니다. 총기 폭을 포함한 짧은 검사 세 개를 공간 그리드에서 수행하며, 실제 문·창문 구멍은 막지 않습니다. 1인칭 손/총의 별도 깊이 패스와 조준점은 유지하고, 서버의 발사 원점·벽 차폐·명중 판정은 변경하지 않습니다.

무기 색상: **FIELD ISSUE / NEON CIRCUIT / EMBER FORGE / ARCTIC GHOST / BIOHAZARD / PHANTOM HEX**. 모든 색상은 무료입니다. 무기는 **1–4번만 기본 개방**, 나머지는 장비실에서 미리보기 후 LP로 영구 해금합니다. 잠긴 무기는 랭크를 포함해 출격/사망 선택으로 사용할 수 없습니다. 로그인 시 계정 구매, 비로그인 시 기기 구매를 사용하며 기존 기록은 보존합니다.

### 개인 무기 숙련도

각 무기로 누적 **50킬 → Lv1, 150킬 → Lv2, 350킬 → Lv3, 750킬 → Lv4, 1,550킬 → Lv5**이며 이후 추가 필요 킬은 1,600·3,200…으로 두 배씩 늘어납니다. 킬마다 타이머 아래에 해당 무기 레벨과 다음 레벨 게이지를 표시하고, 상대의 사망 화면에도 처치자의 해당 무기 레벨을 표시합니다. **레벨에 따른 피해·체력 보너스는 없습니다.** 무기별 킬은 라운드 ID/단조 증가 원장으로 중복 저장을 막고, 중도 이탈해도 기록을 유지합니다. 기존 프로필의 과거 누적 킬을 임의로 무기별 배분하지 않으므로 기존 무기별 기록은 Lv0에서 시작합니다.

### 총기 Lv.5 소음기 (무료 선택 장착)

- 해당 총기 **누적 1,550킬**에서만 해금합니다. 기기 장비실과 온라인 출격 장비의 **소음기 장착** 체크박스로 선택하며, 다음 출격·대기실 장비·부활부터 적용합니다. 살아 있는 총을 즉시 바꾸지 않습니다.
- 피해량·탄 퍼짐·사거리·이동속도·줌은 그대로입니다. 총성 게인은 32%, 원격 청취 범위는 45m → 22m로 줄이고 고음을 낮춥니다. 속이 빈 3D 소음기와 줄어든 총구 섬광은 1인칭·다른 플레이어·드롭·미리보기에 동일하게 반영합니다.
- 비로그인 기기 기록과 계정 숙련도는 별도입니다. 로그인 시 계정 장비와 숙련도를 모든 모드에 공통 적용하며, 계정 숙련도는 Spring의 실제 랭크 무기별 킬만 인정합니다. 소음기가 총기의 영구 소유권을 부여하지는 않습니다.
- 주운 소음기는 해당 총에 붙은 상태로 임시 사용할 수 있지만 해금이나 부활 기본 선택을 바꾸지 않습니다. 튜토리얼·사용자 대전·거점/방어전의 킬로 해금 숙련도를 올릴 수 없습니다.

## 기기 자동 프로필·전적·포인트

- 첫 진입 시 무작위 ID를 만들고 같은 저장소에 다시 접속하면 자동으로 인식합니다. **실제 호스트명, OS 계정명, MAC 주소 또는 IP를 식별자로 수집하지 않습니다.** 콜사인은 사용자가 선택한 게임 이름입니다.
- 웹/Vercel/일반 LAN 브라우저: **같은 사이트 주소(origin)의 같은 브라우저 로컬 저장소**에 저장합니다. 주소나 브라우저가 다르면 별도 프로필이며 브라우저 데이터를 지우면 사라집니다.
- Windows 패키지: 사용자 설정 폴더의 `LINKSHOT/profile.json`에 저장하며, 브라우저에도 임시 사본과 미완료 저장 요청을 보관합니다. 기존 파일이 손상되면 함부로 덮어쓰지 않고 브라우저 임시 저장으로 안내합니다.
- 킬/데스는 플레이 중에도 누적합니다. K/D는 `킬 / max(1, 데스)`, 킬 비율은 `킬 / (킬 + 데스)`입니다.
- **포인트는 라운드 종료 후에만** `완주 50 + 킬 × 20 + 승리 100 LP`로 지급합니다. 중도 이탈 시 전적은 남지만 종료 보상은 없습니다. 완료된 라운드 ID를 기록해 반복 스냅샷/새로고침에 중복 지급하지 않습니다.
- Windows 저장 API는 포인트 숫자 전체를 임의 덮어쓰는 요청 대신 라운드 정산/구매/장착 작업을 순서대로 처리합니다. 잔액 부족과 중복 구매를 검증합니다.
- **기기 프로필은 계정 로그인·클라우드 동기화·변조 방지형 경쟁 경제가 아닙니다.** 기기 소유자는 로컬 파일이나 브라우저 데이터를 직접 수정할 수 있습니다. 온라인 계정·LP·레이팅은 Spring/PostgreSQL이 별도로 관리하며 기기 값을 신뢰하거나 가져오지 않습니다.

### 오퍼레이터 선택 (무료)

메인 화면은 **개인전·팀전별 전적과 우측 상단 LP**를 보여줍니다. 오퍼레이터 카드 또는 LP 버튼에서 외형 상점을 열 수 있습니다. 기존 **KAEL·LYRA**와 함께 **NARI**(밤색 단발·민트), **RHEA**(플럼색 포니테일·크림/라일락), **JIN**(인디고 헤어·블루)을 선택할 수 있습니다.

다섯 캐릭터 모두 무료이며 보유한 전투복을 추가 구매 없이 공유합니다. 선택은 다음 출격에 반영하고 온라인 계정 또는 비로그인 기기 프로필에 저장합니다. **체력·이동·피격 범위는 동일하고 서 있는 1.8m/앉은 1.1m 판정도 바뀌지 않습니다.**

다섯 캐릭터는 **Quaternius CC0의 남녀 인체 리그와 손 메시**를 공유합니다. 새 캐릭터의 헤어는 시안을 보고 별도 3D 메시로 제작했으며, 실제로 선택해 플레이할 수 있습니다.

### 1인칭 손과 파지 자세

**남녀 인체 모델에서 추출한 실제 좌우 손 메시**를 사용합니다. 손가락 마디/엄지의 원래 본으로 방아쇠 손·전방 받침 손·권총 양손 파지를 만들고, 무기별 총열덮개/펌프 위치에 맞춰 배치합니다. 소매와 커프스는 장착 재킷의 색을 따릅니다. 도크야드만 장갑이 손 전체를 덮습니다. 산탄총의 받침 손은 실제 펌프 이동을 따라갑니다.

**모든 총과 나이프의 양팔**에 중립 손목과 직선 전완을 적용합니다. SMG/P90·산탄총·LMG·DMR·권총에 남아 있던 곡선 소매를 제거해 팔뚝이 고무관처럼 휘지 않습니다. 무기별 파지 위치/회전은 `public/weapon-grips.js`의 무기 로컬 손 고정점으로 관리하며, 반동·ADS·펌프와 손이 같은 좌표계에서 이동합니다. 소매는 손목으로 완만하게 좁아지고 넓은 FOV에서도 팔 시작점/팔꿈치를 화면 밖에 둡니다. 총의 조준점과 기존 방아쇠 손/권총 손바닥의 위치는 유지합니다.

참고한 방식: [Unreal Two Bone IK의 무기 파지·손 회전/관절 타깃](https://dev.epicgames.com/documentation/en-us/unreal-engine/two-bone-ik?application_version=4.27), [Unity Two Bone IK의 Target/Hint/회전 분리](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html), [FPS 무기 로컬 IK와 펌프 고정점](https://zaggoth.wordpress.com/author/zaggoth/). 다른 게임의 모델/애니메이션을 복제하거나 엔진 전체를 교체하지 않으며, 3인칭은 기존 2본 IK, 1인칭은 화면 밖 팔꿈치와 강체 전완을 사용합니다.

손과 총은 별도의 깊이 패스로 그려 **서로 뚫고 보이지 않으면서 가까운 벽에 잘리지 않게** 했습니다. 정조준 위치/FOV와 서버로 보내는 조준각·피해·피격 범위는 유지하고, 비조준 표시 위치는 양손이 덜 잘리도록 조정했습니다. 준비된 손 모양은 경기 단위로 공유해 매 프레임 손가락 스키닝을 계산하지 않으며, 경기 종료 때 메시/재질을 해제합니다.

재장전에서는 총기 유형에 따라 손과 탄창·탄피·산탄 모델이 함께 움직입니다. 펌프 산탄총은 빠진 탄만큼 하나씩 삽입되는 연출을, S686은 열리는 총열과 개별 탄, LMG는 덮개와 탄띠, P90은 상부 탄창 교체를 보여줍니다. **시각 효과만 바뀌며** 기존 서버 재장전 시간·실제 탄 보충 시점·무기별 장전음은 유지됩니다.

## `~/engine` 애셋 제작

맵 컨셉과 무기·의복 재질은 **`~/engine`의 로컬 ComfyUI + Animagine XL 4.0 Opt**로 생성합니다. 상점 카드는 게임의 WebGL 모델에서 따로 렌더링합니다. 3D 인체 베이스는 별도 라이선스의 **Quaternius Universal Base Characters Standard(CC0)**입니다. 유료 Source 모델은 사용하지 않습니다. 지형·장비·의복 보강·IK/자세·효과는 프로젝트 코드로 제작합니다. 엔진이 꺼져 있어도 커밋된 GLB/PNG/WAV로 실행되며 빌드는 필요한 모델·소리까지 검증합니다.

총성은 **Tabasco의 CC0 실제 사격 녹음**에서 고립된 한 발만 추출하고 잡음 제거·필터링·정규화와 뒤따르는 반사음/기계음 억제를 거친 고정 샘플입니다. AK·M4의 한 샘플 안에 여러 격발이 섞이던 문제를 제거했습니다. 무기마다 매번 같은 파일/음높이를 사용하며 임의 변형이나 장전음 같은 합성 대체음을 재생하지 않습니다. 발사 예측과 서버 확인은 방아쇠 순번/탄 순번으로 매칭하므로 지연·중복 ACK가 같은 총성을 다시 재생하지 않습니다. 거리 감쇠/좌우 방향/실내 잔향과 동시 발음 제한·리미터를 적용합니다. 파일 출처/라이선스는 [`public/assets/THIRD_PARTY.md`](public/assets/THIRD_PARTY.md)와 소리 manifest에 기록되어 있습니다.

SG-12·SPAS-12·S686은 넓은 저중역 타격감과 짧고 조밀한 잔향을 추가한 별도 샷건 프로필입니다. SPAS-12는 더 묵직하게, S686은 더 짧고 날카롭게 구분하고, 장전 녹음도 조금 더 선명하게 믹싱합니다. 기존 CC0 원본과 고정 음높이·한 발당 한 총성·소음기 감쇠·리미터는 유지합니다.

**SR–1 / AWP / Barrett M82**는 저음 몸체를 보강한 고정 단발 샘플과 각각 **1.65 / 1.95 / 2.20초**의 길고 확산되는 잔향을 사용합니다. 녹음 속 다음 격발이나 볼트 소리를 붙인 것이 아니라, 고립된 한 발에 저음·잔향을 가공한 것입니다. 기존 샘플은 유지하면서 재생 게인을 **2배(+6dB)**, 저음은 추가 **2dB** 높여 발사 충격을 보강했습니다. 출력 리미터로 중첩 소리의 과부하를 완화하며 실제 출력 증가량은 볼륨·동시 소리에 따라 달라집니다. 소음기 장착 시에는 저음 추가 증폭을 제거하고 감쇠합니다. 같은 총은 매번 같은 파일과 재생 속도 1을 유지하며 기존 비저격 17종 녹음은 바꾸지 않습니다.

발소리와 킬 확인음은 `public/sound-design.js`의 자체 합성 신호를 사용하며 추가 외부 샘플·음성 API가 필요하지 않습니다. 발소리는 좌우 발을 번갈아 재생하고 주변 소리는 거리·층 높이·카메라 방향을 반영합니다. 벽 뒤에서는 작고 둔탁하게 들리되 시야 밖이라는 이유로 완전히 사라지지는 않습니다. 청취 거리는 기본 달리기 최대 26m·앉기 14m이며 실제 음량은 거리와 자세에 따라 줄어듭니다. **Shift 걷기는 청취 거리와 관계없이 로컬·원격 모두 무음**이며, 조용히 이동한 거리는 보폭에 쌓지 않으므로 키를 놓아도 발소리가 몰려 나오지 않습니다. 보폭은 프레임 속도에 의존하지 않고, 발소리 동시 재생 수를 제한합니다. 킬 확인음은 본인의 확정 처치에만 나고 마지막 라운드 킬에도 재생되며, 빠른 연속킬에서는 앞선 잔향을 부드럽게 줄입니다. 모두 설정의 효과음 볼륨·음소거를 따릅니다.

총알이 내 캐릭터 가까이를 지나가면 실제 탄도가 지나간 방향에서 짧은 스침음이 납니다. 벽에 막힌 탄이나 나를 맞힌 탄에는 스침음을 겹치지 않으며, 산탄도 한 발에 가장 가까운 소리 하나만 냅니다. 실제 피해를 받으면 명중 확인음과 구분되는 짧고 낮은 타격음이 나고, 헤드샷은 조금 더 날카롭게 들립니다. 기존 음량·음소거를 따르며 전투 판정을 바꾸지 않습니다.

발소리는 **약 120ms의 짧고 낮고 단단한 뒤꿈치→앞꿈치 ‘도각’ 접지음**입니다. 주된 접지 음정을 약 250Hz로 낮추고 날카로운 고음·잡음·좌우 발의 음정 차이를 줄였습니다. 기본 달리기는 2600Hz, 앉기는 1900Hz 저역 통과 필터를 기본으로 쓰며 거리·엄폐에 따라 더 둔탁해집니다. 낮은 주파수의 잔여 편향도 제거해 긴 울림이나 끌리는 꼬리는 남기지 않습니다.

다른 캐릭터의 보폭은 서버/워커의 누적 지상 이동거리로 계산합니다. 20Hz 상태가 정지 순간에 도착하거나 보간 중 순간 속도가 0이 되어도 이미 걸은 보폭이 사라지지 않습니다. 짧은 정지는 350ms 동안 보폭을 유지하며 공중·사망·순간이동은 별도로 억제합니다. 주변 발소리의 과도한 거리/엄폐 이중 감쇠를 완화하되 앉기 소리는 여전히 조용하고 벽 뒤에서는 둔탁해집니다.

장전음은 전자음 대신 **zer0_sol의 CC0 실제 탄창·슬라이드·탄피 삽입·펌프 녹음**을 사용합니다. 로컬 ComfyUI의 오디오 볼륨/EQ 노드로 헤드룸과 선명도를 조정한 뒤, 23종 각각에 맞춰 탄창 교체·볼트·펌프·탄띠/쌍발 삽입 동작과 배율/타이밍을 별도로 편집했습니다. 샘플 길이는 실제 무기 장전 시간과 같고 네트워크 지연이 있으면 해당 시점부터 재생하며, 사망·부활·장비 변경·취소에는 이전 장전음을 멈춥니다. 엔진은 제작 때만 사용하고 플레이/빌드에는 커밋된 WAV와 `reload-manifest.json`만 필요합니다.

```sh
npm run assets:characters

# 준비된 CC0 남녀 모델에서 1인칭 손·손가락 본/재질 추출 (NumPy/Pillow)

# 실제 3D 인물 사진 재생성 (격리된 헤드리스 브라우저는 종료 후 자동 정리)
node scripts/render-characters.mjs
# 실제 녹음 기반 장전음 23종 준비 + 로컬 ComfyUI 오디오 EQ 처리
~/engine/.venv/bin/python scripts/prepare-reloads.py --engine
# 기존 녹음은 유지하고 지정한 신규 총성·장전음만 준비
~/engine/.venv/bin/python scripts/prepare-audio.py --only an94,s686,vector
~/engine/.venv/bin/python scripts/prepare-reloads.py --only an94,s686,vector
```

- 프롬프트/시드/모델 출처: `public/assets/asset-manifest.json`
- 재현 가능한 API 워크플로: 생성 시 `artifacts/workflows/`에 저장
- 모델 라이선스: **CreativeML Open RAIL++-M** — [모델 카드](https://huggingface.co/cagliostrolab/animagine-xl-4.0). 생성물 배포 시 모델의 사용 제한과 별도 권리 문제를 확인하세요.
- 기존 엔진의 출력 디렉터리를 변경하지 않으며 PreviewImage 결과를 이 프로젝트로 가져옵니다.
- 재생성 이미지는 무시되는 `artifacts/asset-staging/`에 먼저 쓴 뒤 교체하므로 생성 중인 파일이 웹 화면에 노출되지 않습니다.

### 프레임 지연 진단

그래픽 설정은 기존 **표준**(화면 배율 최대 1.65·2048 그림자), **균형 · 성능 권장**(배율 최대 1·1024 그림자), **낮음**(배율 최대 0.75·그림자/장식 조명 없음)입니다. 기존 설정은 유지되며 고해상도 화면에서 GPU 부하가 크면 균형부터 비교하세요. 인게임 FPS는 실제 렌더 횟수를 기준으로 표시하며, 표시 위에 마우스를 올리면 최근 120프레임의 프레임 시간/CPU 작업 시간 p95와 드로콜·삼각형 수를 확인할 수 있습니다. CPU 수치는 JavaScript와 렌더 명령 제출 시간이지 GPU 실행 시간은 아닙니다. 메뉴에서는 실제 렌더를 10Hz로 제한합니다.

캐릭터 IK는 임시 수학 객체를 재사용하고 중복 행렬 갱신을 줄입니다. 가까운 화면 내 상대는 매 프레임, 먼 상대는 최대 30Hz, 화면 밖 상대는 그림자를 위해 최대 10Hz로 자세만 갱신하며 사망한 상대는 생략합니다. 이동·보간·발소리·권위 충돌/명중 판정은 이 제한과 독립적입니다. 탄흔 보정은 정적 맵의 개별 인스턴스를 공간별로 찾아 주변 표면만 검사하고 변경된 GPU 버퍼 구간만 전송합니다. 시체는 그래픽 준비 때 만든 모델과 만료된 모델을 최대 8개까지 보관해 재사용하며, 활성 시체도 최대 8개이고 퇴장 때 보관 자원을 모두 해제합니다.

기존 산업/도심 맵의 컨테이너 골·상자·장식 기둥도 같은 재질/그림자 설정별로 인스턴싱합니다. 16m 구역으로 나눠 화면 밖 소품 제외를 유지하며, 기존 건물·식물원·시장 배치와 권위 충돌 데이터는 그대로 사용합니다. 인스턴스 전용 GPU 버퍼도 퇴장 때 해제합니다.

`npm run benchmark:performance`는 별도 헤드리스 브라우저·임시 로컬 서버에서 캐릭터 7명 IK, 탄흔 보정 10회, 시체 생성/회수의 CPU 중앙값과 p95를 출력합니다. 같은 장비에서 전후 비교하는 마이크로벤치마크이며 실제 경기 FPS나 GPU 성능을 보장하는 수치는 아닙니다.

시체 소멸이 시작될 때 불투명→반투명 셰이더가 처음 컴파일되어 생기던 큰 멈춤을 줄였습니다. 교전 전 그래픽 준비 화면에서 무기·캐릭터·반투명 시체·피격 효과의 셰이더와 버퍼를 미리 준비하고, 시체는 처음부터 같은 투명 모드로 유지합니다. 캐릭터의 변경되지 않는 메시 버퍼도 경기 단위로 공유하고 경기 종료 때 한 번 해제합니다.

부활·바닥 총 교체에 대비해 월드용 무기 24종(나이프 포함) × 텍스처 유무 2가지의 벽 가림 셰이더와 1인칭 소음기 버퍼도 미리 준비합니다. 준비된 재질은 경기 종료까지 보관해 프로그램이 캐시에서 제거되지 않게 하며, 처음 보는 무기나 스킨을 표시할 때 교전 도중 다시 컴파일하는 일을 줄입니다.

그래픽 준비 중 다른 참가자가 나가거나 장비가 바뀌면 해당 재질의 해제를 셰이더 컴파일 완료 뒤로 미룹니다. 준비 도중 본인이 로비로 나가도 GPU 자원은 컴파일이 끝난 뒤 안전하게 정리하므로, 드라이버가 아직 참조하는 프로그램을 먼저 지워 로딩이 중단되는 문제를 방지합니다.

`BENCH_SECONDS=12 BENCH_MAP=foundry node scripts/benchmark-game.mjs`는 사용자 브라우저/LAN 방과 분리된 헤드리스 7봇 환경을 측정합니다. 프레임/렌더/스냅샷/시체 생성 지표와 CPU 프로필을 공개 제외 경로 `artifacts/`에 저장하고 브라우저·테스트 서버를 종료합니다. 개발 장비의 개선 전 샘플에서 시체 소멸 시 약 1.25초의 렌더 지연을 확인했으며 사전 준비 후 재측정에서 해당 지연은 재현되지 않았습니다. 수치는 하드웨어·장면에 따라 달라지며 모든 종류의 지연이 사라진다는 보장은 아닙니다.

`node scripts/benchmark-lifecycle.mjs <비교할 Git 리비전>`은 시작/메뉴/종료의 CPU·DOM 작업을 비교합니다. 종료 스냅샷 100회에서 반복 점수판 교체/중립 입력을 각각 100회→0회로 줄였고, 잠금 해제 시 불필요한 매 프레임 작업 대신 30Hz 배경 갱신을 사용합니다. GPU 해제는 화면 전환 직후의 한 작업에 몰지 않고 지연 처리합니다. 실제 FPS 개선율을 보장하는 수치는 아닙니다.

실행 중인 `npm start`는 공통 서버 모듈을 메모리에 유지하므로, 서버 규칙/맵을 업데이트했다면 **진행 중인 방을 종료한 뒤 서버를 재시작하고 브라우저도 새로고침**하세요. 새 클라이언트가 이전 프로토콜의 방에 진입하려 하면 재시작 안내를 표시해 오래된 충돌/사격 규칙과 섞이지 않게 합니다. 브라우저 프로필/포인트는 서버 재시작으로 삭제되지 않습니다.

Windows EXE는 정적 사이트와 로컬 프로필 API를 내장한 Go 표준 라이브러리 런처입니다.
