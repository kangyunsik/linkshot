# Spring 온라인 서비스 — 로컬 개발 기반

**Java 21 · Spring Boot 4.1.2 · PostgreSQL 18.3**. 기존 Node LAN 서버와 브라우저 워커는 유지하고, 온라인 전투도 `shared/`의 같은 JS 규칙을 별도 실행 노드에서 사용합니다.

## 현재 구현 범위

- 아이디/비밀번호 회원가입·로그인·로그아웃, BCrypt 12, 로그인 시 세션 ID 교체.
- PostgreSQL에 계정·서버 소유 전적/LP/해금/숙련도와 JDBC 세션 저장. 기기 프로필을 업로드/이전하는 API는 없습니다.
- HttpOnly·`/api` 경로 전용 쿠키, CSRF, 명시적 CORS 목록, 요청 크기/인증 시도 제한.
- 서버 배정 경기 계약, 엔진 점유/하트비트, 60초·일회용·해시 저장 접속권.
- 원래 JS 엔진에서 판정한 경기 결과만 엔진 전용 인증으로 정산. 참가자·AI 수·킬/데스·무기 장부를 확인하고 같은 경기를 중복 지급하지 않습니다.
- JS 게이트웨이에서 생존/사망 장비 규칙과 재접속 생명·탄약을 유지합니다. 랭크 슬롯에 AI를 넣는 경로는 없으며 Java와 JS 양쪽에서 AI 배정을 거부합니다.
- 비정상 종료/만료된 엔진 점유는 계정을 해제하고 보상을 지급하지 않습니다.
- 일반·랭크별 대기열, 대기 취소/하트비트, 무작위 맵, 전투 노드의 실제 가용 용량 확인.
- 일반/랭크 실력 점수 분리, 랭크 10회 배치·자동 승급/강등·챌린저 상위 200명, 중복 지급을 막는 불변 정산 영수증과 최근 20경기 API.

`/api/health`의 `matchmaking`은 엔진 인증 설정과 최근 15초 이내의 노드 하트비트가 있어야 `true`입니다. 노드가 없으면 계정 기능만 사용하며 매칭은 준비되지 않았다고 표시합니다. 경기 생성은 Spring 매칭 서비스만 호출하며 브라우저에 임의 생성 API를 열지 않습니다. 새 온라인 계정은 로컬 LP와 관계없이 **0 LP·기본 4종**으로 시작합니다. 로비의 기존 장비실·외형 상점은 기기 프로필 전용이며 온라인 구매 UI는 아직 제공하지 않습니다.

## 초기 매칭·경쟁 규칙

- 두 모드 모두 로그인 필수, **4인 개인전·20킬/5분**, 8개 전장 무작위. 진행 중인 경기에 새 사람/AI를 추가하지 않습니다.
- 일반은 30초 동안 사람을 기다린 뒤 부족한 자리를 `BOT` 표식의 AI로 채웁니다. 평균 일반 실력 점수가 1100 미만이면 초급, 1100–1499는 중급, 1500 이상은 고급 AI입니다.
- 랭크는 사람이 4명 모일 때까지 기다리며 시간 제한/AI 보충이 없습니다. **20종 총을 경기 안에서만 임시 허용**하고 영구 소유권/상점 LP는 바꾸지 않습니다.
- 두 실력 점수는 각각 1000에서 시작합니다. 매칭 허용 폭은 먼저 기다린 사용자를 기준으로 ±150에서 15초마다 50씩 늘어나 최대 ±600입니다. 별도의 지역/핑 기반 매칭은 아직 없습니다.
- 일반은 **사람 상대 킬/데스만** 비교하는 쌍별 Elo(K=24), 랭크는 전체 사람 순위로 Elo(K=32)를 적용합니다. 각 쌍은 `K / (인원−1) × (실제 결과−기대값)`을 반올림해 반영합니다. 기대값은 점수 차이/400의 표준 Elo 식이며 동점은 0.5입니다. 사람 간 처치가 없으면 점수가 변하지 않지만 랭크 탈주는 예외입니다. AI 상대 성적은 일반 레이팅을 올리지 않습니다.
- 랭크는 **10회 배치** 후 최초 티어를 실력 점수로 결정합니다(최대 골드 I, 1000점은 실버 V). 이후 상위 절반은 약 +15–35, 하위 절반은 약 −15–35 승급점수를 얻으며 경계 동점은 0입니다. 실력/현재 단계 차이로 조정하고 100점마다 **자동 승급**, 하한을 넘으면 **즉시 강등**합니다. 승급전·강등 보호·휴면·시즌 초기화는 없습니다.
- 브론즈→실버→골드→플래티넘→다이아 각각 V–I. 챌린저는 **다이아 I/100점·배치 완료·랭크 20경기·실력 점수 2600 이상** 중 점수순 상위 200명만 부여하며 매 랭크 정산 때 재검사합니다.
- 접속 종료 유예는 **30초**입니다. 같은 플레이어 객체/생명/탄약을 유지하지만 전투는 계속되어 피격/사망할 수 있습니다. 만료 후 탈주로 기록하고 LP 전부를 지급하지 않으며 최하위로 계산합니다. 랭크 실력 점수는 최소 16 감소하고 배치 후 승급점수도 하위권으로 반영합니다. AI로 대체하지 않습니다.
- 일반 보상과 랭크 보상은 `완주 50 + 킬당 20 + 1위 100 LP`. 서버가 판정한 전적/숙련도와 별도로 저장하며 탈주자는 보상이 없습니다. 경기 종료 뒤 끊겼다는 이유로 완료된 결과를 탈주로 바꾸지 않습니다.

이 값들은 초기 프로토타입 정책이며 특정 게임의 과거 경쟁 규칙을 완전히 복제한 것이 아닙니다.

## Docker 없이 개발

Node 22 이상, `npm install`, Java 21, Maven 3.6.3 이상이 필요합니다. 개발용 PostgreSQL 바이너리는 Maven의 테스트 의존성으로 내려받으며 시스템 DB를 설치하거나 기존 DB를 변경하지 않습니다. 일반 사용자로 실행하세요.

### 간편 실행 (macOS/Linux)

프로젝트 루트에서 터미널 세 개를 열어 순서대로 실행합니다.

```sh
./spring.sh  # 터미널 1: Spring + 개발용 PostgreSQL (기본 8080)
./online.sh  # 터미널 2: Node.js 온라인 전투 서버 (기본 8090)
./fe.sh      # 터미널 3: 온라인 FE 빌드 + 미리보기 (기본 4173)
```

브라우저는 **http://127.0.0.1:4173**으로 접속합니다. 각 터미널에서 `Ctrl+C`로 종료합니다. 다른 디렉터리에서 스크립트의 전체 경로로 실행해도 프로젝트 루트를 찾아갑니다. Spring/전투 스크립트는 비밀 설정이 없으면 생성하고 기존 `online-server/.env`는 보존합니다. macOS에서는 Java 21을 자동 선택하며, 다른 환경에서는 Java 21이 PATH에 있거나 `JAVA_HOME`으로 지정되어 있어야 합니다.

`fe.sh`는 명시한 `ONLINE_SERVER_URL`, `.env`의 `ONLINE_SERVER_URL`, `.env`/환경의 `ONLINE_API_URL`, 기본 `http://127.0.0.1:8080` 순으로 API 주소를 사용합니다. 포트를 바꾸면 `FRONTEND_ORIGINS`도 FE origin에 맞춰 설정하세요. 스크립트는 LAN용 `npm run dev`를 변경하거나 기존 서버를 종료하지 않습니다.

### 같은 LAN의 다른 PC에서 온라인 모드 접속

위 기본 설정은 **서버 PC 한 대 안에서만** 사용할 때의 설정입니다. 다른 PC의 `127.0.0.1`은 그 PC 자신이므로 서버 주소로 사용할 수 없습니다. 실행 중인 세 스크립트를 `Ctrl+C`로 종료한 뒤, 서버 PC에서 다음과 같이 실행합니다.

```sh
./spring.sh --lan  # 터미널 1: 사설 IPv4 자동 선택 + LAN 설정 저장
./online.sh        # 터미널 2: 저장한 LAN 설정으로 실행
./fe.sh            # 터미널 3: LAN API 주소로 다시 빌드
```

서버 PC와 다른 PC **모두 `fe.sh`가 출력한 같은 LAN 주소**로 접속하세요. 자동 선택이 다른 인터페이스를 골랐다면 `./spring.sh --lan <서버의-사설-IPv4>`로 지정할 수 있습니다. 설정은 비공개 `online-server/.env`에만 남으며 비밀번호·엔진 비밀키·기존 DB/계정은 유지됩니다. 다음 실행부터는 옵션 없이 세 스크립트를 실행해도 저장한 설정을 사용합니다. `npm run online:config -- --lan`으로 설정만 저장하거나 `--local`로 PC 한 대 전용 설정으로 되돌릴 수도 있습니다.

LAN 모드는 Spring HTTP API와 전투 WebSocket만 모든 인터페이스에 바인딩하고, **DB와 엔진→Spring 내부 주소는 루프백에 유지**합니다. CORS/전투 접속 출처는 선택한 FE origin 하나만 허용하며 `*`로 풀지 않습니다. 방화벽에서 **4173·8080·8090 TCP**를 신뢰하는 사설망에만 허용하세요. 개발용 HTTP이므로 신뢰할 수 있는 LAN에서만 사용하고 공유기 포트포워딩/인터넷 공개에는 사용하지 마세요. 기본 Compose의 루프백 포트 공개 설정은 이 옵션으로 바뀌지 않습니다.

### 개별 npm 명령

```sh
npm run online:config
npm run online:dev
```

다른 터미널에서:

```sh
npm run online:engine
```

프런트엔드는 다음과 같이 선택적으로 API 주소를 넣어 빌드합니다. 튜토리얼·혼자 연습은 여전히 서버 없이 동작합니다.

```sh
ONLINE_SERVER_URL=http://127.0.0.1:8080 npm run build
npm run preview
```

PC 한 대에서는 `http://127.0.0.1:4173`, 여러 PC에서는 위 LAN 모드가 출력한 주소에서 일반/랭크 탭의 계정 패널을 이용합니다. 로그인 후 매칭 버튼을 누르면 대기 인원/시간/AI 여부가 표시되고 배정 시 자동 입장합니다. 대기 취소와 배정된 경기 재접속 버튼도 제공됩니다. FE/API는 같은 호스트명을 사용해야 쿠키가 정상 동작합니다. 다른 포트를 쓰면 `.env`의 `FRONTEND_ORIGINS`를 해당 origin으로 바꿉니다. Java 선택이 필요하면 `JAVA_HOME`을 설치된 Java 21에 맞춥니다.

`online:config`는 무작위 비밀값을 `online-server/.env`에 0600 권한으로 생성하고 값은 출력하지 않습니다. 옵션이 없으면 기존 파일을 보존하며, `--lan`/`--local`은 네트워크 설정만 원자적으로 갱신합니다. 개발 DB는 `data/online-dev/`에 남아 재시작 후에도 계정을 유지하며, 테스트 DB는 `online-server/target/` 아래에 격리합니다. 두 경로와 `.env`는 Git/배포 대상이 아닙니다. **DB는 로컬 전용이며 인터넷에 노출하면 안 됩니다.**

## Docker Compose 대안

```sh
npm run online:config
docker compose --env-file online-server/.env -f compose.online.yml up --build
```

API 8080, 전투 노드 8090, DB 5432는 모두 호스트 루프백에만 바인딩합니다. Compose는 별도의 `online-db` 볼륨을 사용하며 Docker 없는 개발 DB와 섞이지 않습니다. 실제 운영 배포·TLS·도메인·백업·비밀번호 복구/계정 운영 정책은 별도 설정이 필요합니다. 현재 개발 환경에는 Docker가 없어 Compose 실행 자체는 검증하지 않았습니다.

## 경계와 연결 계약

```text
정적 FE ── /api/auth/*, /api/account, /api/queue ── Spring + PostgreSQL
       └─ 일회용 접속권 ── WebSocket 전투 노드 ── shared JS Room
                                └─ 엔진 전용 /internal/* 정산 ── Spring
```

브라우저는 세션 쿠키/CSRF를 사용하고 엔진 비밀키를 받지 않습니다. `ENGINE_SECRET`은 Spring과 전투 노드 사이에서만 공유합니다. 접속권은 WebSocket 첫 인증 메시지로 보내며 URL·브라우저 저장소·로그에 남기지 않습니다. 클라이언트가 제출한 사용자 ID·보유 무기·점수·결과는 신뢰하지 않습니다. 정산 영수증은 해당 경기 참여자 본인에게만 열며 `GET /api/results`는 본인의 최근 20경기, `GET /api/results/{id}`는 경기별 당시 점수/티어를 반환합니다.

외부 HTTPS FE를 쓸 때 API/WS에도 HTTPS/WSS가 필요합니다. 쿠키는 기본 `SameSite=Lax`; 서로 다른 사이트 배포가 필요하면 TLS 뒤에서 `COOKIE_SECURE=true`, `COOKIE_SAME_SITE=none`과 정확한 `FRONTEND_ORIGINS`를 설정합니다. `none`과 비보안 쿠키 조합은 서버가 거부합니다. 개발 구성을 그대로 포트포워딩해 공개하지 마세요.

## 검증

```sh
npm test
npm run test:online
ONLINE_BROWSER_TEST=1 npm run test:e2e -- tests/browser/online.spec.js
```

마지막 명령은 Playwright 브라우저가 설치된 환경에서 실제 회원가입/로그인·로컬 LP 보존·일반 AI 보충·랭크 4인 대기/입장·임시 무기/영구 소유권 분리·재접속 상태 보존을 검사합니다. 통합 테스트는 **실제 PostgreSQL과 실제 Spring HTTP 서버**를 사용하고 Node 전투 노드의 두 WebSocket 접속·처치·정산, 대기열·점수 분리·배치/승급/강등·탈주·챌린저 정원도 검증합니다. 개인 프로필이나 실제 운영 DB를 테스트 데이터로 사용하지 않습니다.

의존성 라이선스: Spring/대부분의 빌드 라이브러리는 Apache-2.0, PostgreSQL은 PostgreSQL License, 테스트용 `io.zonky.test:embedded-postgres`는 Apache-2.0입니다. 모델·이미지·기존 엔진 원본이나 Windows 패키지를 온라인 서버 소스에 포함하지 않습니다.
