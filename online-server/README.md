# Spring 온라인 서비스 — 로컬 개발 기반

**Java 21 · Spring Boot 4.1.2 · PostgreSQL 18.3**. 기존 Node LAN 서버와 브라우저 워커는 유지하고, 온라인 전투도 `shared/`의 같은 JS 규칙을 별도 실행 노드에서 사용합니다.

## 현재 구현 범위

- 아이디/비밀번호 회원가입·로그인·로그아웃, BCrypt 12, 로그인 시 세션 ID 교체.
- 가입 시 콜사인은 받지 않고 아이디를 표시 이름으로 사용합니다. 로그인 후 프로필에서만 온라인 콜사인을 변경할 수 있습니다. 아이디 중복 확인은 비밀번호 입력 전에 이용할 수 있으며, 최종 가입도 DB 유니크 제약으로 보호합니다.
- PostgreSQL에 계정·서버 소유 전적/LP/해금/숙련도와 JDBC 세션 저장. 기기 프로필을 업로드/이전하는 API는 없습니다.
- HttpOnly·`/api` 경로 전용 쿠키, CSRF, 명시적 CORS 목록, 요청 크기/인증 시도 제한.
- 서버 배정 경기 계약, 엔진 점유/하트비트, 60초·일회용·해시 저장 접속권.
- 원래 JS 엔진에서 판정한 경기 결과만 엔진 전용 인증으로 정산. 참가자·AI 수·킬/데스·무기 장부를 확인하고 같은 경기를 중복 지급하지 않습니다.
- JS 게이트웨이에서 생존/사망 장비 규칙과 재접속 생명·탄약을 유지합니다. 임시 랭크 AI는 서버 배정에 명시된 경우만 허용하며, 브라우저가 임의로 AI 수/정책을 지정할 수 없습니다.
- 비정상 종료/만료된 엔진 점유는 계정을 해제하고 보상을 지급하지 않습니다.
- 일반·랭크별 대기열, 대기 취소/하트비트, 무작위 맵, 전투 노드의 실제 가용 용량 확인.
- 개인전/팀전 **티어·MMR·RP·배치 5판을 독립 관리**하며 챌린저 정원도 모드별 200명입니다. 계정 API의 `competitive.ffa` / `competitive.teams`는 모드별 승률·K/DA와 최근 10경기를 반환합니다.
- 비밀번호는 **8자 이상·UTF-8 72바이트 이하**입니다. BCrypt 작업 강도는 기존 12를 유지합니다.
- 플레이어 마크는 개인전/팀전 중 높은 공식 티어입니다. LAN의 선택적 마크 확인은 V12의 60초·엔진 한정·일회용 티켓을 사용하며 큐를 취소하거나 계정/방 정체성을 바꾸지 않습니다. 마크 확인 실패는 LAN 플레이를 막지 않습니다.
- WAN 사용자 대전의 계정 인증 접속권, 전투 노드의 방 목록·선택적 scrypt 비밀번호·개인전/팀전·방장 재경기. 사용자 방 결과는 경쟁 진행도에 정산하지 않습니다.

`/api/health`의 `matchmaking`은 엔진 인증 설정과 최근 15초 이내의 노드 하트비트가 있어야 `true`입니다. 노드가 없으면 계정 기능만 사용하며 매칭은 준비되지 않았다고 표시합니다. 경기 생성은 Spring만 호출합니다. 새 계정은 **0 LP·기본 4종**으로 시작하며, 로그인 시 공통 장비실·외형 상점의 구매/장착은 계정 LP로 처리합니다. V14는 외형 소유권을 보존합니다. 구매 API는 세션/CSRF와 DB 잔액 잠금으로 서버 가격·소유권·중복 차감을 검증합니다.

## 초기 매칭·경쟁 규칙

- 두 모드 모두 로그인 필수. **개인전 랭크(4인·기본 20킬)**, **팀전 랭크(3:3·팀 합산 40킬)**이며 기본 5분, 8개 전장 무작위입니다. 진행 중인 경기에 새 사람/AI를 추가하지 않습니다.
- V13의 영속 수락 창은 15초입니다. `POST /api/queue/respond`는 세션/CSRF로 본인의 `matchId`에만 응답합니다. 수락이 끝나기 전에는 엔진 pending/claim/ticket을 차단합니다. 거절/만료된 인간은 실제 정산 명단에서 제거하고 팀을 유지한 채 AI로 대체합니다. 검색 AI 비활성화와 관계없이 미수락 대체는 허용하며 전원 미수락은 취소합니다.
- 첫 그래픽 준비 완료 때 공통 시작 시각을 정합니다. 늦은 로더와 재접속은 남은 시간만 보고, 시각 이후에도 준비 중인 인간이 있으면 최대 30초 준비 제한 안에서 기다린 뒤 추가 카운트 없이 함께 시작합니다. 준비 중 F 전체화면과 E 공통 장비실을 허용하며 서버가 이동·사격·피해를 차단합니다.
- 30초 동안 사람을 기다린 뒤 부족한 자리를 `BOT` 표식의 AI로 채웁니다. 개인전은 4명, 팀전은 6명이 먼저 모이면 AI 없이 바로 시작합니다.
- `RANKED_AI_ENABLED=false`로 바꾸고 Spring을 재시작하면 이후 팀전 랭크는 사람 6명을 기다립니다. 이미 배정된 경기의 AI 허용 여부는 DB의 경기 계약에 보존합니다.
- AI의 기준 실력 점수는 배정 시 해당 모드 참가자 점수 평균으로 고정합니다. 1100 미만이면 초급, 1100–1499는 중급, 1500 이상은 고급 AI입니다. 내부 엔진 통신에만 전달하고 AI용 계정이나 영구 점수는 만들지 않습니다.
- 개인전·팀전 랭크는 **기본 총기와 계정 구매 총기만 허용**합니다. 입장·준비·부활 모두 중앙 소유권을 검증하며 위조된 브라우저 목록을 신뢰하지 않습니다. 계정 구매 장비는 LAN·연습·사용자 대전에서도 공통 사용합니다. 소음기는 해당 총기의 계정 Lv.5(누적 1,550킬)에서 무료 장착합니다.
- 두 실력 점수는 각각 1000에서 시작합니다. 매칭 허용 폭은 먼저 기다린 사용자를 기준으로 ±150에서 15초마다 50씩 늘어나 최대 ±600입니다. 별도의 지역/핑 기반 매칭은 아직 없습니다.
- 개인전은 킬/데스 순위의 쌍별 Elo(K=24), 팀전은 양 팀 평균 실력과 팀 승패의 Elo(K=32)를 사용합니다. 팀 점수는 팀 합산 킬이며 개인 MVP가 패배 팀의 승리를 가져가지 않습니다. 동점은 0, 탈주는 패배·최소 실력 점수 16 감소입니다.
- 개인전·팀전 각각 **5회 배치** 후 최초 티어를 결정합니다(최대 골드 I, 1000점은 실버 V). 100 RP마다 승급하고 하한을 넘으면 강등합니다. V10은 기존 팀전 티어를 보존하고 V11은 기존 개인전 MMR·완료 기록을 이용해 개인전 티어를 초기화합니다. 과거 영수증과 LP는 덮어쓰지 않습니다.
- 브론즈→실버→골드→플래티넘→다이아 각각 V–I. 챌린저는 **다이아 I/100점·배치 완료·랭크 20경기·실력 점수 2600 이상** 중 점수순 상위 200명만 부여하며 매 랭크 정산 때 재검사합니다.
- 접속 종료 유예는 **30초**입니다. 같은 플레이어 객체/생명/탄약을 유지하지만 전투는 계속되어 피격/사망할 수 있습니다. 만료 후 탈주로 기록하고 LP 전부를 지급하지 않으며 최하위로 계산합니다. 랭크 실력 점수는 최소 16 감소하고 배치 후 승급점수도 하위권으로 반영합니다. AI로 대체하지 않습니다.
- 보상은 `완주 50 + 킬당 20 + 승리 100 LP`이며 팀전 승리 보상은 승리 팀의 모든 비탈주자에게 지급합니다. 영수증의 RP·승급/강등·배치 진행은 승패 이펙트 5초 후 애니메이션으로 표시합니다. 로그인하면 모든 모드의 메인/상점에 동일한 계정 LP를 표시하고 비로그인 기기 지갑은 별도로 보존합니다.
- 메인 전적 스트립의 일반 점수·랭크 티어는 온라인 계정 값입니다. 기기 프로필의 누적 전적·상점 잔액은 그대로 보존하며, 대기 화면에서는 점수 허용 폭/AI 정책 문구를 생략합니다.

이 값들은 초기 프로토타입 정책이며 특정 게임의 과거 경쟁 규칙을 완전히 복제한 것이 아닙니다.

## WAN 사용자 대전과 LAN 팀전

FE 우측 상단의 **프로필**에서 로그인·회원가입한 후 여섯 번째 **사용자 대전** 탭을 선택하면 공통 온라인 전투 노드에 연결합니다. 메인 화면에 인증 폼이나 방 설정을 펼치지 않고, 생성·목록·비밀번호·무기 선택은 각각 모달에서 수행합니다. 방을 만들면 전장이 아니라 팀 대기실로 먼저 입장합니다. 참가자는 자신의 팀·출격 무기·준비 상태를 선택하고 방장은 대기 중인 사람과 AI의 팀을 배치하며 팀별 AI를 추가·제거합니다. AI마다 추가할 때 난이도를 지정할 수 있고, 준비되지 않은 사람이 있거나 한 팀이 비어 있으면 시작을 거부합니다.

대기 중인 참가자는 서버가 이동·사격·피격·자동 부활·완주 보상에서 제외합니다. 기존 교전이 진행 중이면 새 참가자는 대기실에서 팀·장비를 정한 뒤 입장하며 기존 생명·탄약·경기 시계는 초기화하지 않습니다. 경기 종료 후 다시 대기실에서 준비할 수 있습니다. 마지막 사람이 나가면 방을 지우고 방장은 남은 사람에게 넘깁니다. 개인전·팀전 랭크의 5초 카운트다운은 로비가 아닌 **실제 전장 위**에 표시합니다.

`POST /api/custom/ticket`은 로그인/CSRF가 필요하며 60초·일회용·해시 저장 접속권만 발급합니다. 브라우저는 이를 WS 첫 프레임에 보내고, 노드는 엔진 전용 `/internal/custom/consume-ticket`으로 계정의 실제 보유 장비를 확인합니다. 접속권은 선택된 노드와 계정에 묶입니다. 중앙 선택 노드를 유지해 사용자들이 같은 방 목록을 보도록 하고, 노드 하트비트가 만료되면 다른 노드로 전환할 수 있습니다.

방·비밀번호 해시는 **전투 노드 메모리**에만 존재합니다. 노드 재시작/장애로 해당 방은 종료되며 영구 방 저장·진행 중 경기 이전 기능은 없습니다. 비밀번호 원문/해시는 목록·스냅샷·초대 링크에 넣지 않습니다. WAN의 잘못된 비밀번호 시도는 계정 기준으로 제한하며 사용자 방은 점수·전적·LP·영구 숙련도 정산 API를 호출하지 않습니다. 기존 계정·구매·일반/랭크 기록은 별도로 유지합니다.

실제 인터넷 WAN 접속에는 외부에서 접근 가능한 **HTTPS API·WSS 전투 노드·정확한 FE 허용 출처**를 설정해야 합니다. `--lan`은 같은 사설망의 여러 PC에서 이 온라인 흐름을 검증하는 개발 모드이지 공인 IP 배포 기능이 아닙니다. 공유기 포트포워딩이나 AWS/TLS 배포를 자동 실행하지 않습니다. LAN 방은 기존 Node LAN 서버 페이지에서 같은 생성/목록/비밀번호 UI를 이용합니다.

## Docker 없이 개발

Node 22 이상, `npm install`, Java 21, Maven 3.6.3 이상이 필요합니다. 개발용 PostgreSQL 바이너리는 Maven의 테스트 의존성으로 내려받으며 시스템 DB를 설치하거나 기존 DB를 변경하지 않습니다. 일반 사용자로 실행하세요.

### 간편 실행 (macOS/Linux)

**LAN만 플레이할 때는 Node 22 이상과 `npm install` 후 터미널 두 개만 실행합니다. Spring·Java·DB·로그인은 필요하지 않습니다.**

```sh
./online.sh  # 터미널 1: LAN + 온라인 전투 노드
./fe.sh      # 터미널 2: FE + 동일 출처 LAN 프록시
```

같은 PC는 **http://127.0.0.1:4173**, 같은 사설망의 다른 PC는 **http://<서버의-사설-IP>:4173**으로 접속합니다. FE의 `/lan/play`와 Node의 게스트 LAN 방은 인증된 `/play`·온라인 전적과 분리되며 계정 API가 중단되어도 작동합니다. 사설 HTTP FE 호스트의 동일 포트만 LAN 출처로 허용하고, 온라인 출처 제한은 완화하지 않습니다.

**계정·랭크·온라인 사용자 방**까지 사용하려면 Spring을 추가합니다.

```sh
./spring.sh  # 터미널 1: Spring + 개발용 PostgreSQL (기본 8080)
./online.sh  # 터미널 2: Node.js 온라인 전투 서버 (기본 8090)
./fe.sh      # 터미널 3: 온라인 FE 빌드 + 미리보기 (기본 4173)
```

브라우저는 **http://127.0.0.1:4173**으로 접속합니다. 각 터미널에서 `Ctrl+C`로 종료합니다. 다른 디렉터리에서 스크립트의 전체 경로로 실행해도 프로젝트 루트를 찾아갑니다. Spring/전투 스크립트는 비밀 설정이 없으면 생성하고 기존 `online-server/.env`는 보존합니다. macOS에서는 Java 21을 자동 선택하며, 다른 환경에서는 Java 21이 PATH에 있거나 `JAVA_HOME`으로 지정되어 있어야 합니다.

Spring은 계정·DB·매칭·정산, Node 전투 노드는 실시간 이동·총알·AI·룸 동기화, FE는 화면 제공을 담당하는 별도 프로세스입니다. LAN 설정을 유지해도 **이 PC에서는 `127.0.0.1` 또는 `localhost`로 접속**할 수 있으므로 CORS 때문에 `--local`을 줄 필요는 없습니다. 개발용 사설 HTTP FE origin에는 동일 포트의 두 루프백 origin을 Spring과 전투 서버가 함께 추가합니다. FE와 API가 같은 사설 호스트로 설정된 빌드는 루프백 접속 시 API 및 전투 접속권 주소도 해당 루프백 호스트로 맞춥니다. 분리된 API 호스트·공개 서버·HTTPS/WSS 인증서 주소는 재작성하지 않습니다.

다른 PC에서 서버의 사설 IP로 FE에 접속하면 브라우저의 API·전투 접속권에 남아 있는 `localhost`/`127.0.0.1`은 **현재 접속한 서버 IP**로 보정합니다. 예를 들어 서버 FE가 `http://<서버 IP>:4173`이면 API는 같은 서버의 `:8080`을 호출합니다. 단, 실행 중인 Spring/Node가 루프백에만 바인딩돼 있으면 URL만 바꿔서는 접근할 수 없습니다. `node scripts/create-online-env.mjs --lan <서버 IP>`로 설정하고 **세 서버를 재시작**해야 합니다. DB와 내부 엔진→Spring API는 계속 루프백을 사용합니다.

**기존 버전에서 갱신할 때:** 진행 중인 경기를 마친 뒤 Spring·전투 노드·FE를 종료하고 위 세 스크립트를 다시 실행한 후 모든 브라우저를 새로고침하세요. 현재 전투 프로토콜은 **22**이며 구버전 노드에는 접속권을 보내기 전에 버전 오류를 표시합니다. 소음기 상태를 장비·발사·드롭 스냅샷으로 전달합니다. Spring의 V8 마이그레이션은 장착한 소음기 선택 테이블만 추가하며 V7의 콜사인 확장도 유지합니다. **기존 DB·계정·구매·전적을 삭제하거나 초기화할 필요가 없습니다.** 노드 재시작 시 메모리의 사용자 방은 종료됩니다.

`fe.sh`는 명시한 `ONLINE_SERVER_URL`, `.env`의 `ONLINE_SERVER_URL`, `.env`/환경의 `ONLINE_API_URL`, 기본 `http://127.0.0.1:8080` 순으로 계정 API 주소를 사용합니다. LAN 프록시 대상은 `LAN_ENGINE_URL`, 기본 `ws://127.0.0.1:<ENGINE_PORT>/lan/play`입니다. 프록시 주소와 비밀키를 정적 빌드에 넣지 않습니다. 스크립트는 기존 서버를 종료하지 않습니다.

### 같은 LAN의 다른 PC에서 온라인 모드 접속

위 기본 설정은 **서버 PC 한 대 안에서만** 사용할 때의 설정입니다. 다른 PC의 `127.0.0.1`은 그 PC 자신이므로 서버 주소로 사용할 수 없습니다. 실행 중인 세 스크립트를 `Ctrl+C`로 종료한 뒤, 서버 PC에서 다음과 같이 실행합니다.

```sh
./spring.sh --lan  # 터미널 1: 사설 IPv4 자동 선택 + LAN 설정 저장
./online.sh        # 터미널 2: 저장한 LAN 설정으로 실행
./fe.sh            # 터미널 3: LAN API 주소로 다시 빌드
```

다른 PC는 **`fe.sh`가 출력한 LAN 주소**로 접속하고, 서버 PC 자신은 같은 주소 또는 `127.0.0.1`/`localhost`를 사용할 수 있습니다. 자동 선택이 다른 인터페이스를 골랐다면 `./spring.sh --lan <서버의-사설-IPv4>`로 지정할 수 있습니다. 설정은 비공개 `online-server/.env`에만 남으며 비밀번호·엔진 비밀키·기존 DB/계정은 유지됩니다. 다음 실행부터는 옵션 없이 세 스크립트를 실행해도 저장한 설정을 사용합니다. `npm run online:config -- --lan`으로 설정만 저장하거나 `--local`로 수신 인터페이스 자체를 PC 한 대 전용으로 제한할 수도 있습니다.

LAN 모드는 Spring HTTP API와 전투 WebSocket만 모든 인터페이스에 바인딩하고, **DB와 엔진→Spring 내부 주소는 루프백에 유지**합니다. CORS/전투 접속 출처는 설정한 FE origin과 같은 포트의 루프백 별칭만 허용하며 `*`로 풀지 않습니다. 방화벽에서 **4173·8080·8090 TCP**를 신뢰하는 사설망에만 허용하세요. 개발용 HTTP이므로 신뢰할 수 있는 LAN에서만 사용하고 공유기 포트포워딩/인터넷 공개에는 사용하지 마세요. 기본 Compose의 루프백 포트 공개 설정은 이 옵션으로 바뀌지 않습니다.

### 개별 npm 명령

```sh
npm run online:config
npm run online:dev
```

다른 터미널에서:

```sh
npm run online:engine
```

프런트엔드는 다음과 같이 선택적으로 API 주소를 넣어 빌드합니다. 튜토리얼·혼자 연습은 여전히 서버 없이 동작합니다.

```sh
ONLINE_SERVER_URL=http://127.0.0.1:8080 npm run build
npm run preview
```

PC 한 대에서는 `http://127.0.0.1:4173`, 여러 PC에서는 위 LAN 모드가 출력한 주소에서 **우측 상단 프로필의 계정 모달**을 이용합니다. 매칭 버튼을 누르면 메인의 같은 자리에 검색 인원/시간과 취소가 표시됩니다. 발견한 경기를 직접 수락하면 전장으로 이동하고 공통 서버 시작 시각의 남은 시간을 봅니다. FE/API는 같은 호스트명을 사용해야 쿠키가 정상 동작합니다. 다른 포트는 `.env`의 `FRONTEND_ORIGINS`에 등록합니다.

`online:config`는 무작위 비밀값을 `online-server/.env`에 0600 권한으로 생성하고 값은 출력하지 않습니다. 옵션이 없으면 기존 파일을 보존하며, `--lan`/`--local`은 네트워크 설정만 원자적으로 갱신합니다. 개발 DB는 `data/online-dev/`에 남아 재시작 후에도 계정을 유지하며, 테스트 DB는 `online-server/target/` 아래에 격리합니다. 두 경로와 `.env`는 Git/배포 대상이 아닙니다. **DB는 로컬 전용이며 인터넷에 노출하면 안 됩니다.**

### 아이디 중복 확인과 온라인 콜사인

- `GET /api/auth/username-availability?username=...`: 영문/숫자/_ 3–24자, 대소문자 구분 없는 중복 확인입니다. 비밀번호 없이 확인하며 `username`과 `available`만 반환합니다. 인증 시도와 별도의 요청 제한을 사용합니다.
- `POST /api/auth/register`: 아이디·비밀번호만 받습니다. 이미 존재하는 아이디면 **409 / 이미 존재하는 아이디입니다**로 실패하며 비밀번호를 바꾸거나 로그인하지 않습니다. 동시에 가입해도 DB 유니크 제약으로 하나만 생성됩니다.
- `POST /api/account/callsign`: 로그인·CSRF가 필요한 표시 이름 변경입니다. 계정 ID는 요청에서 받지 않고 인증된 본인의 계정만 수정합니다. 콜사인 1–24자를 저장하되 아이디·비밀번호·전적·기기 프로필은 바꾸지 않습니다. 기존 전장에는 다음 입장부터 반영합니다.
- `POST /api/account/weapons/{weaponId}/suppressor`: 로그인·CSRF가 필요한 무료 소음기 선택입니다. 본문의 `{ "equipped": true/false }`만 받고 DB의 무기별 1,550킬을 확인합니다. 나이프·다른 계정·위조 숙련도 필드는 허용하지 않습니다. 선택 목록은 계정의 `suppressedWeapons`로 반환하고 다음 출격/부활부터 적용합니다. 무기 소유권이나 LP는 바꾸지 않으며, 기기 프로필과도 동기화하지 않습니다.

## Docker Compose 대안

```sh
npm run online:config
docker compose --env-file online-server/.env -f compose.online.yml up --build
```

API 8080, 전투 노드 8090, DB 5432는 모두 호스트 루프백에만 바인딩합니다. Compose는 별도의 `online-db` 볼륨을 사용하며 Docker 없는 개발 DB와 섞이지 않습니다. 실제 운영 배포·TLS·도메인·백업·비밀번호 복구/계정 운영 정책은 별도 설정이 필요합니다. 현재 개발 환경에는 Docker가 없어 Compose 실행 자체는 검증하지 않았습니다.

## 경계와 연결 계약

```text
정적 FE ── /api/auth/*, /api/account, /api/queue ── Spring + PostgreSQL
       └─ 일회용 접속권 ── WebSocket 전투 노드 ── shared JS Room
                                └─ 엔진 전용 /internal/* 정산 ── Spring
```

브라우저는 세션 쿠키/CSRF를 사용하고 엔진 비밀키를 받지 않습니다. `ENGINE_SECRET`은 Spring과 전투 노드 사이에서만 공유합니다. 접속권은 WebSocket 첫 인증 메시지로 보내며 URL·브라우저 저장소·로그에 남기지 않습니다. 클라이언트가 제출한 사용자 ID·보유 무기·점수·결과는 신뢰하지 않습니다. 정산 영수증은 해당 경기 참여자 본인에게만 열며 `GET /api/results`는 본인의 최근 20경기, `GET /api/results/{id}`는 경기별 당시 점수/티어를 반환합니다.

외부 HTTPS FE를 쓸 때 API/WS에도 HTTPS/WSS가 필요합니다. 쿠키는 기본 `SameSite=Lax`; 서로 다른 사이트 배포가 필요하면 TLS 뒤에서 `COOKIE_SECURE=true`, `COOKIE_SAME_SITE=none`과 정확한 `FRONTEND_ORIGINS`를 설정합니다. `none`과 비보안 쿠키 조합은 서버가 거부합니다. 개발 구성을 그대로 포트포워딩해 공개하지 마세요.
